外部クライアントは `cataclysm-bn-tiles --client=mcp` の stdio 上で、改行区切りの JSON-RPC 2.0 によりゲームをプレイします。値は [Draft 2020-12 スキーマ](../../../schema/engine-client/0.2.schema.json)で定義され、以下の例はすべて[例ファイル](../../../schema/engine-client/0.2.examples/)でスキーマに照らして検証されています。従来の MCP ツール(`bn.observe`、`bn.press` など)は別の面であり変更されません。クライアントが `bn.hello` を呼ぶと、これらのツールは入力を拒否します。

## セッション

```text
-> {"jsonrpc":"2.0","id":1,"method":"bn.hello","params":{"versions":["0.2"],"client":{"name":"my-client","version":"1"},"schema":"sha256:0123456789abcdef"}}
<- {"jsonrpc":"2.0","id":1,"result":{"version":"0.2","epoch":"epoch:e7f3","engine":{"build":"...","mods":["bn"],"display":{"tiles":true,"tileset":"UNDEAD_PEOPLE_BASE"},"sound":{"soundpack":"/opt/bn/data/sound/Basic"}},"limits":{"frame_bytes":1048576,"cells_per_part":512,"cells_per_query":4096,"screen_queue":8},"schema":"sha256:0123456789abcdef","locale":"en","engine_locale":"en","role":"controller"}}
-> {"jsonrpc":"2.0","id":2,"method":"bn.subscribe","params":{}}
<- {"jsonrpc":"2.0","id":2,"result":{"at":{"epoch":"epoch:e7f3","sequence":"40","revision":"31"},"interaction":{...},"entities":[],"parts":1}}
<- {"jsonrpc":"2.0","method":"bn.snapshot.part","params":{"epoch":"epoch:e7f3","at":{...},"index":0,"last":true,"cells":[...]}}
-> {"jsonrpc":"2.0","id":3,"method":"bn.command.submit","params":{"epoch":"epoch:e7f3","expect":{"revision":"31","boundary_id":"boundary:90","schema_id":null},"operation":{"kind":"action","action_id":"RIGHT"}}}
<- {"jsonrpc":"2.0","id":3,"result":{"epoch":"epoch:e7f3","command_id":"c:5","stage":"received"}}
<- {"jsonrpc":"2.0","method":"bn.command","params":{"epoch":"epoch:e7f3","command_id":"c:5","stage":"validated"}}
<- {"jsonrpc":"2.0","method":"bn.command","params":{"epoch":"epoch:e7f3","command_id":"c:5","stage":"executing"}}
<- {"jsonrpc":"2.0","method":"bn.events","params":{"epoch":"epoch:e7f3","events":[{"sequence":"41","revision":"32","type":"interaction.changed","command":"c:5","changes":{...}}]}}
<- {"jsonrpc":"2.0","method":"bn.command","params":{"epoch":"epoch:e7f3","command_id":"c:5","stage":"completed","at":{"epoch":"epoch:e7f3","sequence":"41","revision":"32"}}}
```

`parts` 個のスナップショットパートを集めてから、`bn.events` を順に適用します。欠落(gap)、epoch の不一致、`bn.resync` があれば `bn.subscribe` を再度呼びます。新しいスナップショットは状態のみを復元し、`lost_after` 以降の一時的なイベントは失われたものとして扱われ、再送されません。 エンジンはイベント履歴を保持しません。`bn.unsubscribe` の後や遅れた後に戻る方法は `bn.subscribe` だけで、そのスナップショット(再送ではない)が最後に見た `(epoch, sequence)` に取って代わります。`bn.resync` が止めるのはイベントだけで、スナップショットに含まれない `bn.command` のステージは届き続けます。ステージはその `at` より新しいスナップショットの後に届くこともあります。ステージがプッシュされるのは `bn.subscribe` から `bn.unsubscribe` または `bn.hello` までで、その間以外のコマンドの結果は `bn.command.result` で読みます。古い `epoch` を指定したリクエストはすべて `stale_epoch` と `action: "subscribe"` で失敗します。

エンジンからの通知は `bn.snapshot.part`、`bn.events`、`bn.command`、`bn.resync`、`bn.loading`、`bn.progress` です。`bn.loading` と `bn.progress` 以外は、購読中のクライアントへ入力境界ごとに送られます。`bn.progress`(`{epoch}`)はハートビートで、待機などの行動が入力境界に到達せずに続いている間、`bn.hello` を済ませたクライアントへ 2 秒ごとに送られます。通信が途絶えたなら、エンジンは動いていません。ワールドの読み込み中は `bn.loading` が同じ役割を果たします。

エラーはコード `1000` と `error.data = {kind, action?, at?}` を使い、`action` が次の対応(`hello`、`subscribe`、`retry`)を示します。

## hello とスタック

エンジンはすべてのトランスポートで `"0.2"` だけを提供する。`"0.2"` を列挙しない hello は `negotiation_failed`、`action: "hello"` で失敗する。hello は次を含める必要がある。

- `schema`: `sha256:` と、[`0.2.schema.json`](../../../schema/engine-client/0.2.schema.json) の生バイトの SHA-256 の先頭 16 桁の 16 進数。ハッシュが異なると `negotiation_failed`、`action: "hello"`、`error.data.schema = {engine, client}` で失敗する。エンジンは CMake の構成時にスキーマファイルからハッシュを得る。
- 任意の `locale` と `capabilities`（`tiles`、`tint_ids`、`viewport`、`delivery`。個別メンバーとして送っても受け付けるが両方の形式は併用できない）。結果には `schema`、`locale`（接続のテキストの言語）、`engine_locale`、`role` が加わる。エンジンにカタログのない `locale` は `unavailable_locale`、`action: "hello"` で失敗する。

すべてのインタラクション境界（スナップショットのヘッダーとイベント）は `interaction` と並んで `stack` を持つ。スタックは開いている画面を外側から並べたもので、最後の画面だけが affordance を持つ。画面の `kind` はどの画面か（`map`、`crafting`、`uilist` など）を表し、開くたびに、どの言語でも同じなので、クライアントはウィンドウの位置のように画面ごとに覚えるものをこの値で区別する。`kind` のない画面は、エンジンがまだ名前を付けていない画面である。`component_id` 付きの `bn.interaction.choices` は最上位画面のその一覧（`rows`、`total`）を読む。

`bn.command.submit` は `operation: {kind: "invoke", affordance_id, args?}` を受け取る。`expect` は affordance の `expect` の範囲に従う。

- `screen`: `{screen_id}`。その画面が最上位の間だけ有効で、そうでなければ `stale_screen` で拒否される。エンジンはコマンドの実行中、この種の送信を最大 8 件(hello 結果の `limits.screen_queue`)待たせ、順番が来たときに個別に検証する。キーを押し続けても動き続け、閉じたポップアップ宛てのキーは拒否される。
- `boundary`: `{boundary_id, revision}`。従来どおり。コマンドの実行中は `command_busy` で失敗する。

affordance に合わない形式は `invalid_arguments` である。

オフだが選べる affordance、行、タブ、グリッドのセルには必ず `denial` がある。画面が示した理由をプレイヤーの言語で持ち、なければ今は使えないことを示す。クライアントはこれを理由として表示し、独自の言葉を足さない。

## 押し続けるキー

マップの一歩には `holdable` が付きます。クライアントはキーが下がったときに `bn.hold` を一度、上がったときに `bn.release` を送り、キーリピートには invoke を送りません。hold が有効でマップが最前面の画面で入力待ちの間、エンジンは入力プロンプトごとにネイティブキーをもう一度押したかのようにその操作を一歩ずつゲームへ渡し、一歩の前にクライアントが送済みのリクエストを先に読みます。タップは先に離されても一歩を保証します。ポップアップなど他の画面が上に来る、一歩でアバターのマスもターンも変わらない、新しい `bn.hello`、切断のいずれかで hold は終わります。`bn.hold` は活動中は `not_ready`、最前面でない画面は `stale_screen`、存在しない・hold できない affordance は `unknown_affordance`/`invalid_arguments` で失敗します。画面スコープの invoke はこれまでどおりキューに積まれます(リストで矢印キーを押し続ける場合)。

## 配信クレジット

`bn.hello` の `delivery = {credits, max_hz?}`(`credits` は 1〜256、任意の `max_hz` は 1〜240)で有効にします。結果には `delivery = {credits, held_frames, held_bytes, max_hz?}` が付き、`max_hz` を要求した場合はそのまま返されます。`delivery` を送らない場合、以下は適用されず、プッシュされるフレームは従来どおり入力境界と自動移動のステップで即座に書き込まれます。

- プッシュされる `bn.events` と `bn.command` のフレームは 1 クレジットを消費します。残りがなければエンジンはフレームを順序どおり保持し、`bn.credit {frames}` で追加されたときに書き込みます(結果は付与後の保有クレジットで上限 256。保持されたフレームはレスポンスの後に続きます)。スナップショットの部分、`bn.resync`、`bn.loading`、`bn.progress` はクレジットを消費しません。
- エンジンが 1 つのクライアントのために保持するのは最大 `held_frames` フレーム・`held_bytes` バイトです。どちらかを超えると保持中の `bn.events` を破棄し、理由 `backpressure` の `bn.resync`(`lost_after` は書き込んだ最新の sequence)を送り、クライアントが `bn.subscribe` を呼ぶまでイベントのプッシュを止めます。そのスナップショットが破棄分を置き換えます。保持中の `bn.command` フレームは残り、クレジットが支払われ次第 `bn.resync` の後に届きます。`bn.subscribe` も保持中のイベントだけを破棄するため、コマンドの終わりが失われることはありません。保持の上限を超えるほどステージを未払いのまま残したクライアントだけが、その最も古いものを失います。
- クレジットを持つクライアントは、実行中の行動(待機、製作など)の間もコマンドの完了より前にフレームを受け取ります。ワールドのキャプチャは 1 ターンよりはるかに高価なため、エンジンは毎ターンではなく、発行に要する時間が行動の時間の 5 分の 1 になる間隔でのみ発行し、`max_hz` があれば実時間で 1/`max_hz` 秒に 1 回までという制限も加え、より疎な方に従います。フレームは直前のフレーム以降の変更を担い、状態の変更はまとめられ、すべてのメッセージと演出の事実は順序どおりに含まれ、行動が終わる境界が残りを担います。`bn.command` の `completed` は引き続き入力境界で送られます。ストリームはクライアントを待ちません。クレジットを付与しなくなったクライアントがエンジンに強いるのは保持上限までで、ゲーム、その RNG、セーブは、すべてを読むクライアントや存在しないクライアントの場合と同一です。
- クレジットがアクティビティを待たせることはありません。stdout はコントローラーとしてソケットと同じく扱われる(`ソケットと観戦者` を参照)ため、クレジット済みのフレームはブロックせずに書き込まれるバッファに入り、stdout が満杯でもエンジンは stdin を読み続けます。パイプより大きいフレームはクライアントが読むのを最大 10 ms 待つため、すぐに読むクライアントはフレーム全体を受け取ります。その間に何も読まなかったクライアントは、読むまで再び待たれません。アクティビティの配信より遅く読むクライアントはクレジットが尽き、上記のとおり再同期されます。16 MiB を超えて読まないクライアントはソケットと同じく切断されます。stdio には次のコントローラーがないため、エンジンはプレイ中のゲームを保存して終了します。Windows の stdio はこの扱いではありません。書き込みはパイプが受け取って初めて戻るため、クレジットを渡した分を読まないクライアントをアクティビティは待ちます。

## フレームと失敗

- フレームは 1 行の JSON 値 1 つで、どちらの向きも `limits.frame_bytes` を超えません。フレームは単一の書き込み主体が丸ごと書くため混ざらず、エンジンは一度に 1 フレームだけを読み、それ以上は溜めません。
- JSON でない行には `-32700`、形の誤った JSON には `-32600`、未知の `bn.` メソッドには `-32601`、不正な params には `-32602` で答えます。読み取れる `id` がなければ `id` は `null` で、通知には答えません。このようなフレームはゲームも保留中のフレームも変えず、アクティビティの実行中でも接続は維持されます。
- 最大長を超えるフレームや stdin の終了で途切れたフレームには答えられません。エンジンはそれ以上読まず、理由を stderr に書いて終了コード 1 で終了します(ソケットではその接続だけが終わります)。
- アクティビティの実行中、リクエストには答えますが何も開始しません。`bn.command.submit` は次の入力境界まで `not_ready` で失敗し、`bn.interrupt` はアクティビティが受け付ける唯一の制御で、`bn.viewport`、`bn.subscribe`、`bn.credit` は配信される内容だけを変えます。コマンドはアクティビティが終わる境界まで開いたままです。`bn.hello` を再送すると配信を再交渉し、保留中のフレームを捨てて購読を解除するため、ストリームは次の `bn.subscribe` からやり直します。
- 終了時(stdin の終了、ゲームの終了)、エンジンはクレジットで支払える保留フレームを順に書き込み、残りを捨てます。未完了コマンドの `interrupted` 段階もこれに含まれます。`SIGTERM` と `SIGINT` は stderr にシグナル名を書いてからエンジンを即座に終了させます。読むのをやめて自分側を閉じたクライアントは、失敗した書き込みを通じてエンジンを終了させます。

## ソケットと観戦者

`--client=mcp --listen <path>` は、stdio の代わりに同じプロトコルをローカルのストリームソケット(Unix ドメインソケット。Windows 10 以降では `AF_UNIX`)で提供します。オプションがなければ何も変わりません。エンジンはユーザーだけが読めるファイルを作り、応答のない古いファイルは置き換え、使用中のパスは拒否します。フレームは同じ行で、制限も同じです。同時に処理する接続は最大 8 で、それ以上は直ちに閉じます。ワールドの読み込み中にも接続でき、`bn.loading` を受け取ります。

- **役割。** 最初の接続と、コントローラーがいないときに張られた接続がコントローラーで、ゲームに命令できるのはコントローラーだけです。他の接続は観戦者で、それぞれ独自の `bn.hello`、クレジット、保持フレーム(256 フレーム、1 MiB)、購読を持ちます。観戦者はコントローラーが読めるすべて(コントローラーのコマンドの段階とイベントを含む)を読めますが、`bn.command.submit`、`bn.interrupt`、`bn.viewport`、レガシーの `bn.press` と `bn.interact` は `read_only` で失敗し、観戦者の `bn.hello` はコントローラーのビューポートとタイル設定に触れません。接続中に役割は変わらず、操作したい観戦者はコントローラーが去った後に接続し直します。
- **ブロックしない。** 出力は接続ごとのバッファにブロックせずに書き込まれ(コントローラーのフレームは stdio と同じく読み取りを最大 10 ms 待ちます)、16 MiB を超えて送れなくなった接続は、それ以前にクレジットがストリームを止めていなければ閉じられます。ゲームは stdio と同じくコントローラーの入力だけを待ち、その間に観戦者を処理するため、読むのが遅い、あるいは全く読まない観戦者がゲームやコントローラーを遅らせることはありません。クレジットのためにアクティビティがソケットを待つこともありません。
- **切断。** 接続を閉じるとその接続のために保持していたものはすべて解放され、再接続のために残すものはありません。戻ったクライアントは `bn.hello` と `bn.subscribe` を送り、そのスナップショットから続けます。これは `bn.resync` の後と同じです。JSON でないフレームには上記のとおり答えて接続は維持され、制限を超えたフレームや切断で途切れたフレームはその接続だけを終わらせます(stdio ではエンジンが終了します)。
- **コントローラーが去るとき。** 開いていたコマンドは `interrupted` になります。実行中のアクティビティは最後まで続き、その後ゲームはキーを押していないプレイヤーのように入力境界で接続を待ち、次の接続がコントローラーになります。観戦者は接続されたまま、ゲームの現在位置を知らされます。ソケットが閉じてもエンジンは終了せず、ゲーム自身の終了か `SIGTERM`、`SIGINT` で終了します。

## 単一の時計

- `epoch` はプロセス開始時とワールド入れ替え時に変わり、読み取りでは変わりません。
- `sequence` は公開されたイベントの数です(10進文字列、連続、`"1"` から開始)。`revision` は状態を変えるイベントの数です。`at = {epoch, sequence, revision}` は「sequence までのすべてのイベントを含む」ことを意味します。
- コマンドは `expect = {revision, boundary_id, schema_id}` を持ちます。古い値は拒否されるため、クライアントは見ていない画面に対して操作しません。`schema_id` は、その境界にインタラクションがないときに限り `null` です。

## コマンド

`operation.kind` は `choose`、`fill`、`set_count`、`set_target`、`cancel`(意味ベースのメニュー)、`action`(移動キーなど登録済みの行動)、`travel`(マップのクリック)、または `tile_action`(マップのマスに対する行動、後述)のいずれかです。

```json
{ "kind": "choose", "choice_id": "tab:new_game" }
{ "kind": "set_target", "pos": { "dim": "", "x": 9, "y": 4, "z": 0 } }
{ "kind": "action", "action_id": "RIGHT" }
{ "kind": "travel", "pos": { "dim": "", "x": 9, "y": 4, "z": 0 } }
```

すべての境界アクションは、アクティブな入力コンテキストがそのアクションに割り当てた単一キーボードキーの可搬名(`ESC`、`SPACE`、`RETURN`、`UP`、`>` など)を `keys` に列挙します。`action` はアクションを id で実行し、キーのないアクション(割り当てのない `open_options` など)も実行できます。押されたキーで動作するクライアントは、キー設定ファイルから推測せず、`keys` にそのキーを含むアクションを探してください。

`travel` は、インタラクションのない境界で、画面内の絶対マップマスに対する Tiles と curses の左クリックです。最初のクリックはエンジン自身のルートを `route` として公開し、同じマスをもう一度クリックするとネイティブの自動移動が始まります。その後アバターは 1 歩ずつ歩き、各歩でそのコマンドに紐づく通常のイベントが公開され、エンジンが止まる場所(到着、モンスターの視界入りなど)で止まります。歩行が終わって再び入力を待つとコマンドは `completed` になります。他のコマンドや別のマスのクリックは計画を置き換えるか消します。クライアントがルートを自分で計算することはありません。

クリックや雑用がマスとアイテムに何をするかも、エンジンが決めます。アバターの隣にある、開けられる閉じたドアへの左 `travel` は、ルートのクリックではなくそのドアへの移動(ネイティブの移動がドアを開ける)になります。`pickup` と `drop` は `{ "kind": "pickup" | "drop", "item_id", "count" }` を取ります。`item_id` は `avatar.ground`(pickup)または `avatar.inventory`(drop)の行の `id`、`count` はその行から取る量をネイティブの単位(釘のようなチャージ式アイテムはチャージ数、それ以外はアイテムの個数)で表し、エンジンはメニューで印を付けて確定したときと同じネイティブの拾う・落とす行動を開始します。行 ID はそのスタックが同じである間は変わらず、行がなくなったか `count` に足りない場合、コマンドは `validation_failed` で拒否されます。失敗したコマンドは、ローカライズされた理由を `error_text`(コマンド結果と `bn.command`)または `message`(JSON-RPC エラーの `data`)で伝えます。エンジンが知っている場合は `error` より具体的です(マップウィンドウ外への移動、スタックを超える個数など)。照準画面(種類 `target`: 射撃、投擲、リーチ攻撃、呪文、タレット)は、ネイティブと同じタイトルの `target` パネルで、stats は `range`(最大射程に対する値、射程外なら `bad`)、`elevation`、`targets`、および銃、照準、投擲、呪文、タレットの数値で、その下に `target:map` マップがあります。マップの `target` は `distance`(`distance_metric` による `source` から `current` までの距離。垂直方向を含む)、`status`(`good`、`bad_target`、`out_of_ammo`、`out_of_range`)、`status_text`(ローカライズされた射程と状態の行)、カーソルが飛べる `candidates`、カーソルのマスの `parts` を持ちます。`pos` を渡した `target:move` はカーソルをそのマスに置き、射撃、照準モード、カーソルキーは登録済みアクションです。どのキーでも進み、キーが割り当てられていないポップアップは、選ぶべき選択肢を `interaction.any_key_choice_id` で示します。

`context` は同じマスへの右クリック(SEC_SELECT)です。ネイティブでは隣のマスを調べる、隣のドアを閉じる、足元のアイテムを拾う、見えているモンスターを撃つ、あるいは計画中のルートをまず取り消します。`bn.world.describe` はターミナルウィンドウ内のマスにホバーしたときにネイティブのマウスビューが表示するテキストを返します(範囲外は `validation_failed`)。何も選択も計画もしません。`bn.world.cells` は 1 つの階層の範囲(`min` と `max` を含み、`dim` と `z` が同じで最大 `limits.cells_per_query` マス)でアバターが知っている内容を返します。セルはスナップショットが持つものと同一で、`forgotten` は範囲内のロード済み領域(coverage)で何も分かっていないマスです。反転した範囲や複数階層にまたがる範囲は `validation_failed`、大きすぎる範囲は `resource_limit`、別の `epoch` は `stale_epoch` です。メニューでのホイール 1 ステップは登録済みアクション `SCROLL_UP` または `SCROLL_DOWN` で、エンジンがネイティブのカーソルを 3 行動かします。

`tile_action` は、`bn.world.describe` がマスに対して列挙する `actions` の一つを `action_id` と `pos` で指定し、そのマスでネイティブのアクションが行うことを行います。一覧には今できることだけが、メニューの順に、ネイティブの `label` とプレイヤーの `keys`(`attack`、`talk`、`travel` にはなし)とともに入ります。`attack`(アバターの隣にいる、味方でない見えている生き物)、`fire`(見えているモンスター、遠距離武器を装備中)、`talk`(見えているキャラクター)、`open`・`close`・`pickup`・`examine`(アバターのマスとその周囲8マスで、ネイティブのアクションが行えるもの)、`travel`(アバターが知っているマス。ルートの計画と歩行開始を1つのコマンドで行う)、`look`(常に。そのマスでルック表示を開く)です。そのマスが今列挙していないアクションは `validation_failed` です。クライアントはこの一覧をマスの右クリックメニューとして表示します。

マップ画面は `shortcuts`、つまりショートカットバーのボタンも持ちます。これはデータ(ゲームの JSON の `client_shortcut`: `id`、`action`、`icon`、`glyph`、`order`。MOD は新しい id でボタンを追加し、同じ id で置き換えます)で、各ボタンはマップの入力コンテキストの登録済みアクションを指します。エンジンはそのコンテキストの `label` と `keys`、データの `icon`(不透明なスプライト id)と `glyph`(専用の絵がないときに描くもの)、マップが最前面でそのアクションを受け付ける間 `enabled` を付けて公開します。コンテキストが名前を持たないアクションのボタンは含まれません。`editor` アクションはマップエディタを開き、`DEBUG_EDITOR` 特性がなければ `denial` `You need the Debug Editor trait.` を持ちます。ワールドマップのコンポーネントは `item_lists` も持ちます。クライアントがマップの横に順に表示するアバターのアイテム一覧で、マップが覆われている間も届きます。一覧ごとに行を持つアバターのメンバーを `id`(`avatar.ground`、`avatar.inventory`)、見出しを `label`、行を一覧の外へ移す動作(拾う、落とす)を `verb` として持ち、どちらもローカライズ済みです。クリックは `affordance_id` が指すアフォーダンスの `invoke` です。画面のアフォーダンスは `confirm`・`cancel` のほか、`role` として `navigate`(カーソル・ページ・タブ・スクロール。クライアントはキー、ホイール、クリックで既に扱えます)、`help`(キー割り当てメニュー)、`digit`(数える一覧の個数に打つ一桁。そのキーに割り当てたアクションより先に読み、ネイティブの一覧と同じく次の印が取る個数になるか、その数字で個数の入力欄を開く。クライアントは描かなくてよい)を持つことがあります。

ステージは `received`、`validated`、`executing`、`completed`、または `rejected`、または `interrupted` で、`interrupted` の `error` が理由を示します(ワールドが入れ替わると `stale_epoch`、ゲームが入力を拒否すると `validation_failed`、それ以外は `not_ready`)。どのステージにもプレイヤー向けの翻訳済みの言葉 `stage_text`(`Received.`、`Under way.`、`Refused.` など)が付きます。処理の判断には `stage` の ID を使います。`completed` は入力が再び待たれていることを意味します。待機などの行動は、終わるか、ゲームが何かを尋ねる(ポップアップや中断)まで先に実行されます。その `at` はその境界の終点です。そのため、入力が開くプロンプト(テキスト欄、数量)は、それを運ぶイベントが先に届くので(`bn.resync` の後は、続くスナップショットが運びます) `completed` の到着時には状態に含まれています。そのときプロンプトが無ければ、プロンプトは開かれなかったということです。同時に実行できるコマンドは 1 つです(`command_busy`)。 待機などの行動の実行中もリクエストには応答します。`bn.interrupt` はネイティブの中断キーを押し、行動は Tiles と同様に中止するか尋ね、その質問が次の境界になります。行動中でなければ `not_ready` で失敗します。

## 読み込み画面

ワールドの読み込み中はゲームスレッドが処理中で入力境界に到達しないため、`bn.hello` を済ませたクライアントには、ネイティブの読み込み画面の各ステップで `bn.loading` が送られます(購読の有無は問いません)。進行状況はネイティブクライアントが表示する画面と同じです。`title` は現在のコンテキスト(例: "Loading files")、`entries` はその一覧、`index` は処理中の項目(それ以前は完了)、`image` はネイティブクライアントと同じ方法で選ばれた読み込み画像です。`image.path` はゲームのベースパスからの相対パスで、ファイル名に作者が含まれない場合 `author` は省略されます。読み込み画面が終わると `done` が一度だけ送られ、その後に通常どおり `bn.resync` や `bn.events` が続きます。`epoch` はそのステップを送った時点の epoch です。

```text
<- {"jsonrpc":"2.0","method":"bn.loading","params":{"epoch":"epoch:e7f3","title":"Loading files","entries":["Terrain","Items"],"index":1,"image":{"path":"data/json/loading/Ada_dawn.webp","author":"Ada"}}}
<- {"jsonrpc":"2.0","method":"bn.loading","params":{"epoch":"epoch:e7f3","done":true}}
```

## 値

- `pos = {dim, x, y, z}` は絶対マップマスで、`dim` はゲームのディメンション、プライマリは `""` です。リアリティバブル座標はワイヤ上に現れません。
- `look = {kind, id, glyph, color}` はゲームデータ由来の見た目を持つため、テキストクライアントにタイルセットは不要です。自動壁の地形はアバターが知っている接続に応じた線文字を持ち、記憶されたマスは `memory.terrain` の上に `memory.overlay`（家具、罠、乗り物部品）を保持します。
- `look` は `name`、つまりネイティブの look が表示する翻訳済みのプレイヤー向けの名前（`t_floor` は "wooden floor"）を持つため、テキストや音声のクライアントは ID を読む必要がありません。クリーチャーにはエンティティの `name` を使います。
- タイルクライアントは同じ `look` をゲームのタイルセットで描画します。エンジンだけが知り得る情報（データとネイティブの選択ロジックを持つのはエンジンのため）を公開し、クライアントは再実装しません。`tile`（`id` と異なるスプライト ID。`corpse_<monster>`、`player_male`、`vp_<part>`）、`looks_like`（データのフォールバック連鎖、近い順）、`subtile` と `rotation`（アバターが知っている隣接マスからネイティブの選択が計算したマルチタイルキーと 90 度回転数。接続ロジックは一箇所のみ）、`stack`（山の表示アイテム）、`attitude` と `aware`（モンスターと NPC。ネイティブ表示は重ねて印を付ける）、`health`（傷ついた生物のネイティブの見回し体力バー。埋まった `fifths`（5 分の幾つ）とその `color`）、`tint`（乗り物部品の塗装。タイルセットがスプライトに混ぜる）、`reviving`（蘇る死体があるマス）、`facing`（生物）、マスの `light`（ネイティブの `lit_level`：0 暗い、1 低い、2 明るいのみ、3 照明あり、4 明るい）、`glow`（ネイティブのタイル表示がスプライトに加える色付きの光。光の `color` と `strength` 1〜255）、`environment.season`、アバターの `look`、キャラクターの `overlays`（装備・手持ちアイテム・ミューテーション・バイオニクスを、ネイティブの順に試すスプライト ID を `tile` と `looks_like` に並べた種別 `overlay` の `look` として）です。ファイル、重み付きバリアント、レイヤー、暗転はタイルセットが定めるものでクライアントが担当します。描画順は地形、家具、罠、フィールド、アイテム、乗り物部品、生物で、`fields` と `items` の最後の要素がネイティブ表示で描かれるものです。`light` は視界内のマスだけを対象とします。ゲームの暗い・明るいのみ（0 と 2）はアバターから見えないマスなので、クライアントは通常表示のないマスすべてに hidden 照明スプライトを敷き、`lowlight_dark` や `lowlight_light` の情報は送りません。記憶されたマスは暗く、`light` が 1 のマスは陰影付きで描かれ、スプライトのない ID は `glyph` にフォールバックします。
- 変異のオーバーレイは `mutation`（変異の `id`、`types`、`flags`）を、アバターやエンティティは `traits`（変異の種類ごとの変異 ID）を持ちます。タイルセットの `tints` と `tint_pairs` がこれをキーにして髪、肌、目に色を付けます。環境は `mod_tilesets` として、タイルセットにスプライトを追加するゲームデータのファイルをネイティブの読み込み順に、`base` フォルダ、ファイル内の `index`、`compatibility` に挙げたタイルセットとともに並べます。 セルは、その上の車両の貨物パーツに物が入っているとき `cargo` を持ち、ネイティブ画面はそのパーツを強調します。 装備または手に持つアイテム、バイオニクス、効果のオーバーレイは `tint_keys` を持ちます。タイルセットの `tints` がキーにする ID で、ネイティブ画面が試す順（フラグ、次に ID）です。 hello は `tint_ids` でタイルセットが持つティントの ID を挙げられます。すると地形、家具、モンスター、車両パーツ、アイテムの look はその中に当てはまる `tint_keys`（フラグ、次に ID）を持ち、ティント変数を持つアイテム、地形、家具は `tint_vars`（タイルセットのティントに重ねる色、ブレンド、補正）を持ちます。フィールドの look はネイティブ画面が塗るフィールド種別のティントを `tint` に持ちます。フィールドの種別がその下のアイテムを隠すとき(煙、火、蜘蛛の巣)、フィールドの項目は `hides_items` を持ちます。それが表示中のフィールドである間、ネイティブのタイル画面はアイテムもその強調も描きません。
- ゲームデータが壁 (`WALL`) としてフラグを付けた地形は、見えていても記憶でも `wall: true` を持つため、真上から描くタイルセットを 3D で描くクライアントはスプライトから推測せずに壁を立ち上げられます。窓 (`WINDOW`) は `window: true` も持つため、そのようなクライアントは窓台とまぐさの間を開けておけます。地形と家具はデータの `coverage`、つまり後ろに立つ人を何パーセント覆うか(1〜100、なければ省略)を持つため、そのようなクライアントはテーブルや茂みのように立っているものを覆う分だけ立ち上げられます。
- `view` が映す階で見えていて、ネイティブのタイル画面が透かして見るマス(空中、および樹冠、ガラスの屋根、下りスロープなど床のない地形)は `below` を持ちます。`below` はネイティブのタイル画面がそこに描くマスが何階下かを示します。床のある最初のマス、または何かを覚えている最初のマスが、見えている、覚えている、または車両であればそのマス、そうでなければ下りる途中で見えた何かのある最も低いマスです。そのマスはそれ自体として公開されます。透かして見るマスはその上にあるもの(フィールドなど)を保ち、何もない空中はそれ以外を持たず、透かして見えるものがない何もない空中は公開しません。透かして見るのは見えているマスだけです。
- `interaction` はネイティブのメニューやダイアログです。`columns` の各項目は、安定した翻訳されない名前 `key`(英語の見出しを小文字にして単語を `_` でつないだもの。例 `spell_level`、所持品のセルは `cell0`、`cell1`、…)と翻訳された見出し `label` を持ち、クライアントは `key` だけで列を探します。列は値のネイティブ色名 `color` を持つことがあります。選択肢は `favorite`(お気に入りの呪文)、`color`、`key_color`(行テキストと `hotkey` の色名)、`markup`(ネイティブの色タグ付きの名前)、ネイティブのリストが選択記号を表示する所では `mark`(`glyph` は `+`、`#`、`-`、と `color`)、入れ子の斜線を描く所では `parent_id` と `nest_color` も持ちます。`choices` は最大 200 行ですがサイズにより少なくなることがあるため、残りは `bn.interaction.choices` を `offset = choices.length` から読みます。全体の行数は `choice_total` です。`compat.focus` と `compat.panes` は 1:1 移植のためにネイティブのリスト状態を保持します。クライアントは無視して構いません。`filter` フィールドがネイティブの検索で、`submit: true` で `fill` すると検索し、空の値で解除します。 ネイティブのコールバックが生のキーを自前で判定するメニュー(wish メニュー、技メニュー)は、それらを項目の前に、キー名をラベルにした `action:key:<keycode>` 行として並べます。`choose` でそのキーを押せ、長いメニューでも最初のページに入ります。 呪文メニューは各呪文行に、ネイティブの側面パネルが描く詳細を載せます。`description`(系統、説明、レベル、難易度、経験値、コスト、時間、対象、ダメージ、範囲、射程、持続時間、素材。色タグ付き)と `columns` の `Spell Level`、`Failure Chance`、`Casting Cost`、`Casting Time`、`Range` で、お気に入りの呪文には `favorite` が付きます。お気に入りの切り替え、詠唱妨害の切り替え、ホットキー割り当てのキーは `action:key:<keycode>` 行です。 ネイティブのコールバックが側面パネルを描くメニュー(武術スタイル、変異・モンスター・アイテムのウィッシュメニュー、効果選択、転送ゲート、魔術書の呪文)は、そのパネルの文字列(色タグ付き)を行自身の説明の後ろに `description` として持ちます。行ごとに検索が要るパネル(武術スタイル、ウィッシュのモンスターとアイテム)は選択中の行にだけ付きます。 ネイティブの一覧が行の前にキーを表示する場合(メニュー項目のホットキー、所持品の文字)、その行は `hotkey` にそのキーを文字列で持ちます。そのキーを押すとネイティブと同様に行が選ばれます。操作ボタンの名前は登録済みアクションの `name` です。choice は、その行が実行する登録済みアクションを示す `action_id` を持つことがあります。ゲーム内メインメニューの行が持つので、Options 行は言語を問わず `open_options` です。
- メインメニューは種類が `main_menu` の画面(role `screen`)で、`menu:banner` テキスト(タイトルの絵)と `menu:tabs` タブの分割です。タブはネイティブのタブごとに一つで(`motd`、`new_game`、`load`、`world`、`settings`、`help`、`credits`、`quit`。表示中のタブは `selected`)、表示中のタブはその下に文章を `menu:text` テキスト(MOTD、クレジット)として、または項目を `menu:entries` リストとして持ちます。リストは項目ごとに開く先で名付けられた行(`new_game:tutorial`、`settings:options`、`load:<world>`、`world:create`、`world:<world>`)で、ネイティブのヒントを `description` に持ちます。ID は位置にも言語にも依存しません。タブ ID を渡した `menu:tab` はそのタブを表示し(ヘルプと終了のタブはネイティブのキーと同じくすぐ実行)、行を渡した `menu:entry` は Enter と同じくその項目を実行します。
- 世界選択(選べる世界が二つ以上ある新規ゲーム)は種類が `world_pick` の画面(role `screen`)で、タイトルは `WORLD SELECTION` です。`world_pick` 分割は `hint` スタットが `Pick a world to enter game` の `world_pick:worlds` パネルを持ち、その下に `world_pick:rows` リストがあります。リストはネイティブの全ページにわたる世界ごとの行で、`world:<world>` と名付けられ、ネイティブのラベル `<world> (<saves>)` を持ちます。行を渡した `world_pick:pick` はネイティブのカーソルをその行(とそのページ)に動かし、行への Enter(`bn:activate:world_pick:pick`)はその世界に入ります。リストにない行は `invalid_arguments` で拒否されます。`NEXT_TAB`、`PREV_TAB`、`QUIT` は登録されたアクションのままです。

- 世界の有効な Mod 一覧(それを表示するメインメニューのワールドタブとゲーム中の項目)は種類が `world_mods` の画面(role `screen`)で、タイトルは `ACTIVE WORLD MODS` です。`worldgen:active_mods` 分割は、読み込み順の `mod:<mod id>` 行の `worldgen:active_mods:rows` リストを持つ `worldgen:active_mods` パネル(Mod がない間は `none` スタット `--NO ACTIVE MODS--`)と、カーソル下の Mod の `worldgen:active_mods:details` テキストです。`worldgen:active_mods:pick` はカーソルを動かし、行への Enter(`bn:activate:worldgen:active_mods:pick`)はネイティブの Enter と同じく一覧を閉じます。`CONFIRM` と `QUIT` は画面を閉じます。
- キャラクター作成は種類が `new_character` の画面(role `screen`)で、タイトルは `Character creation` です。`newchar:tabs` タブ(`points`、`scenario`、`profession`、`stats`、`traits`、職業とシナリオが許す場合の `bionics` と `magic`、`skills`、`overview`)の下に `newchar:<tab>:notes` パネルがあり、そのスタットはタブのネイティブの行(最初に `points_left`、次に `hint` など。`hint` はカーソル下の行のコストで、取れるかどうかで `good` か `bad`)で、`newchar:<tab>` `detail` 分割を持ちます。タブ id を渡した `newchar:tab` は間のタブを通ってそのタブへ移ります。各リストの `newchar:<tab>:pick`(特性とバイオニクスのページでは `newchar:<tab>:<page>:pick`)は行へカーソルを動かし、行への Enter(`bn:activate:` の後にその id)はそこでのネイティブの Enter です。ポイント: 世界が許す `points:multi_pool`、`points:one_pool`、`points:freeform` の `newchar:points:rows` リストで、使用中のものが `toggled` です。能力値: `value` 列つきの `stat:str`、`stat:dex`、`stat:int`、`stat:per` の `newchar:stats:rows` リストと `newchar:stats:details` テキストです。特性とバイオニクス: ネイティブのタブが使う `newchar:<tab>:advantage`、`newchar:<tab>:disadvantage`、`newchar:<tab>:neutral` パネルの `newchar:<tab>:pages` 分割で、各パネルは `trait:<id>` か `bionic:<id>` 行の `:rows` リストを持ち、行は `points` 列、取得済みなら `toggled`、シナリオが禁じるなら `denial` を持ちます。フリーフォーム以外では `pools` スタットがあります。職業とシナリオ: ネイティブの `filter` を持つ `newchar:<tab>:list` パネルが、`points` 列つきの `profession:<id>` か `scenario:<id>` 行のフィルター可能な `newchar:<tab>:list:rows` リスト(`FILTER`)を持ち、選ばれたものが `toggled`(世界の都市の大きさで選べないシナリオは `denial`)で、その横に `newchar:profession:details` テキストか `newchar:scenario:details` パネル(`professions`、`location`、`vehicle`、`flags` スタット)があります。`sort` スタットと、職業では `gender` もあります。スキル: `skill:<id>` 行(`level`、`profession`、`cost` 列)の上に `skill_type:<id>` 見出しがある `newchar:skills:rows` リストと - クラフトメニューは種類が `crafting` の画面(role `screen`)です。`crafting:tabs` カテゴリタブ(`CC_WEAPON`、...)の下に選択中カテゴリの `crafting:subtabs` タブ(`CSC_WEAPON_BASHING`、...。空なら無効)、その下に `crafting:body` detail 分割があります。検索中は 2 つのタブが `search` タブ 1 つに、一括クラフトでは `batch` タブ 1 つになります。`crafting:recipes` リストはレシピごとにレシピ ID で名付けられた行(前に同じものが n 個あれば `#<n>`、一括クラフトでは一括数の `1`、`2`、...)で、`look`、`favorite`、入れ子グループの下では `parent_id`(グループが展開中なら `toggled`)、`availability` 列(`Ready`、`Strained`、`Unlearned`、`Missing`。ネイティブのリストと同じ色)、該当する場合の `known` と `unread` 列、クラフトできないときの `denial` を持ちます。隣の `crafting:detail` パネルは強調中のレシピのもので、完成品の名前をタイトルに、時間、一括での時間短縮、速度補正、作る数、暗所でのクラフト、近くにある数を stats に持ち、`crafting:facts` 分割を含みます: `crafting:description` と `crafting:result`(完成品のネイティブのアイテム情報)テキスト、`crafting:warnings` テキスト、`crafting:primary_skill`、`crafting:other_skills`、`crafting:autolearn` のスキルリスト(`required` と `level` 列、満たしていれば `enabled`)、`requirements:tools` と `requirements:components` リスト(代替ごとに 1 行で、`required` と、ネイティブが数える場合は `available` 列を持ち、手元にあれば `enabled`、複数の代替のグループは親行の下)、`crafting:byproducts` と `crafting:books` リストです。`craft:select` は強調を動かし、`craft:craft`(Enter)はその行をクラフトし、`count` を渡した `craft:batch` はその一括数で一括クラフトに入り、`craft:tab` と `craft:subtab` は ID でタブを選び、テキストを渡した `craft:search` はネイティブの検索で(空なら解除)、`craft:favorite` と `craft:hide` はネイティブのキーと同じくその行を切り替えます。
- 建設メニュー(`*`)は種類が `construction` の画面(role `screen`)です。`construction:tabs` カテゴリタブ(検索中は `FILTER` タブ 1 つ)の下に `construction:body` detail 分割があります。`construction:groups` リストは建設グループごとにグループ ID で名付けられた行で、作るものの `look`、`favorite`、建設できないときの `denial` を持ちます。隣の `construction:detail` パネルは強調中のグループのもので、グループ名をタイトルに、`origin` と `category` の stat を持ち、その下の `construction:stages` 分割にバリエーションごとの `construction:stage:<id>` パネルがあります: 完成物の名前をタイトルに、`Stage/Variant #<n>` をサブタイトルに、移動コスト、破壊に要る力、必要な地形(あるかどうかで `good` か `bad`)、注記、時間、速度補正、地形フラグを stats に持ち、`<panel>:result` テキスト、`<panel>:skills` スキルリスト、クラフトメニューと同じ形の `<panel>:tools` と `<panel>:components` 要件リストを含みます。`construct:select` は強調を動かし、`construct:construct`(Enter)はネイティブの配置を始めて続いて隣接マスを尋ね、`construct:tab` は ID でタブを選び、テキストを渡した `construct:search` はネイティブの検索で(空なら解除)、`construct:favorite` はその行を切り替えます。
- 所持品セレクター(`i` 画面とアイテムピッカー)は種類が `inventory` の画面(role `screen`)です。`inventory` パネルはネイティブのタイトルを画面のタイトルに、その下のヒントをサブタイトルに、有効な `filter` と、ネイティブのウィンドウが表示する場合は容量に対する `weight` と `volume` の stat(超えれば `bad`)を持ち、その下の `split:columns` 分割にネイティブの列ごとのパネル(`panel:inventory`、`panel:worn`、`panel:nearby`、`panel:extra<n>`。`active` はカーソルのある列)があって、それぞれが `list:<column>` リストを持ちます。空のセレクターは `text:empty` テキストです。リストにはカテゴリごとの見出し行(`category:<hash>`、順序で区別)と、スタックごとにアイテムのシリアルで名付けられた行(アイテム 1 つなら `item:<serial>`、複数なら `stack:<最小の serial>`。位置では名付けない)があります。`label` はネイティブの名前セル、`columns` はその後のネイティブのセル(`cell1`、`cell2`、...)で、`hotkey`(アイテムの文字)、`color`、`key_color`、`markup`、`look`、セレクターが拒むときの `denial`、選んでいれば `selected`、カーソル行だけにネイティブのアイテム情報の `description`、複数選択のセレクターでは `mark`、`selected_count`、`minimum_count`、`max` を持ちます。カテゴリ選択中は、カーソルのあるカテゴリの見出しがフォーカスです。`list:<column>:choose` はその文字と同じく行を選び、数を数えるセレクターでは `list:<column>:count` が行の数を決め(0 で印を外し、数はスタックの範囲に収める)、`inventory:digit:<n>`(role `digit`)は次の数の桁を入力します。
- 地面の拾得リストは種類が `pickup` の画面で、`PICKUP_POSITION` オプション(`left`、`right`、`overlapping`、`cursor`)に従って置かれます。`pickup` パネル(タイトル `Pick up`、サブタイトルは出所: 地面、車両の荷台、または近くの地面か車両の荷台。有効な `filter`。容量に対する拾得後の予測 `weight` と `volume` の stat で、ネイティブのヘッダーが赤で表示する場合は `bad`)が `pickup:items` リストを持ちます。スタックごとに所持品と同じくアイテムのシリアルで名付けられた行があり、ネイティブのリストが表示するキーを `hotkey` に持ち、1文字の枠を超えるとバッククォートと2文字になり、それも超えると持ちません。行の `markup` はネイティブのリストが表示する行そのもの(スタック数、`ITEM_SYMBOLS` の記号、自分のものでないアイテムの前の `<color_light_red>!</color>`)で、`label` はそのままです。`parent_id` と `nest_color` は別のスタックに入ったスタックを、`selected`、`mark`、`selected_count`、`max` は印を付けた量を示し、カーソル行はネイティブのアイテム情報を `description` に持ちます。`pickup:toggle`(Enter)はそのキーと同じくスタックに印を付けるか外し、`pickup:count` はその数だけ印を付けます(0 なら外す)。
- 高度な持ち物管理は種類が `advanced_inventory` の画面(role `screen`)で、`aim:pane:left` と `aim:pane:right` パネルの `aim:panes` 分割です(`active` は移動元のペイン)。ペインは `Left pane` か `Right pane` をタイトルに、表示中のエリアか車両とその説明・危険をサブタイトルに、自身の `filter` を持ち、stats は `weight` と `volume`(所持エリアでは容量に対する値で超えれば `bad`、それ以外では体積をエリアの最大値と比べる)、`items`(エリアに最大値があればそれに対する値)、`sort`(ネイティブの並べ替え名)です。ペインは `<pane>:areas` リストを持ちます。ネイティブのエリア選択のエリアごとに 1 行(`area:INVENTORY`、`area:NW`、...、`area:CENTER`、...、`area:ABOVE`、`area:BELOW`、`area:DRAGGED`、`area:ALL`、`area:CONTAINER`、`area:WORN`)で、翻訳済みの `label`、表示中のエリアに `selected`、そこが車両の荷台を表示していれば `toggled`、カーソルのアイテムが入れられないときは `denial` を持ちます。続いて `<pane>:items` リストがあります: カテゴリ順の並べ替え中はカテゴリごとの見出し行(`<pane>:items:category:<id>`)、そしてスタックごとにアイテムのシリアルで名付けられた行で、`amount`、`weight`、`volume` 列(全エリア表示では `source` も)、ネイティブのアイテム情報の `description`、`favorite`、`color`、`look`、`max`(チャージかアイテム数)、自動拾いの対象なら `toggled` を持ちます。移動元の `pane` と `rows`(それぞれ任意の `count`)を渡した `aim:move` はネイティブの移動と同じくそれらをもう一方のペインのエリアへ動かし、動かすものがないか移動先が受け取らないときは `denial` を持ちます。`pane` とエリア行を渡した `aim:set_area` はネイティブのエリアキーと同じくそのペインをそのエリアに向け、`aim:toggle_vehicle` はペインを地面とそこにある車両の荷台の間で切り替え、`pane` とテキストを渡した `aim:filter` はそのペインのフィルターを決め、`aim:close` は閉じます。
- NPC 取引ウィンドウは種類が `trade` の画面(role `screen`)で、取引の種類と NPC をタイトルにします(`Trading with`、`Paying`、`Accepting a reward from`)。`trade:head` パネルの `category_mode` stat がカテゴリ選択がオンかを示し、その中の `trade:panes` 分割に `trade:balance` テキスト(貸し、借り、交換。NPC が受け入れるなら `good`)と、`pane:npc` と `pane:you` のパネル(タイトル `Inventory: <name>`、店主でなければ容量に対する所持の `weight` と `volume`、そのペインの `filter`)があります。各パネルは `list:npc` か `list:you` のリスト(selection `count`)を持ちます: カテゴリごとの見出し行(`trade-category:<hash>`、カテゴリ選択がそこにあれば `selected`)と、スタックごとにアイテムのシリアルで名付けられた行で、`qty`、`weight`、`vol`、`price` 列(価格はアイテムの価値との比較で色付け)、表示中のページの行にだけ `hotkey`、`mark`、`selected_count`、`max`、カーソル行のネイティブのアイテム情報の `description` を持ちます。行と `count` を渡した `trade:set_count` はその行のやり取りする量を決め、`pane` とテキストを渡した `trade:filter` はそのペインを絞り込み、`trade:confirm` と `trade:cancel` は Enter と Escape です。

- 自動販売機は種類が `vending` の画面(role `screen`)で、`vending` 分割です。`vending:items` パネルは `money` スタットがネイティブの `Money left:` 行で、`vending:rows` リストを持ちます。リストはアイテム名ごとにそのアイテムで名付けられた行(`item:<serial>`、位置では名付けない)で、ネイティブのラベル(個数、10 以上は `*`、そして名前)とアイテムの所持品での色を持ちます。強調中のアイテムの `vending:item` パネルは色付きの名前と価格をタイトルにし、アイテム情報を `vending:details` テキストとして持ちます。行を渡した `vending:pick` はネイティブのカーソルをその行に動かし、行への Enter(`bn:activate:vending:pick`)は `CONFIRM` と同じくそのアイテムを買います(キャッシュカードの残高が足りなければネイティブの `You can't afford that item.` ポップアップ)。`QUIT` は離れます。
- ワールドはアバターが知っているものです。`cells`(`remembered`、`visible`、`sensed`)、`entities`、`avatar`(能力値、所持品 `inventory`、足元の `ground`、取り組み中の `activity`。その `name` と、長さの決まった活動なら済んだ千分率 `done`)、`environment`、読み込み済みの `coverage`、`view`、保留中の `route`(計画がなければ空または省略)とその翻訳済みの行 `route_text`(例 `Route of 3 squares; select its end again to go.`。経路がなければ省略)で構成されます。`view` はネイティブの地形ウィンドウが映す階層、つまりアバターの階層か、見回しのカーソルなどのカーソルが移した階層 (`LEVEL_UP`、`LEVEL_DOWN`) で、ネイティブの画面が描くとおりに映すマス `{min, max}` です(アバターに追従します)。`travel` クリックはこの内側だけ受理され、外側は `validation_failed` で拒否されます。
- `avatar.inventory` は手に持つアイテム、装備中のアイテム、持ち運ぶスタックの順に並び、各要素は `{look, name, count?, slot, durability?}` で、`slot` は `wielded`、`worn`、`carried` のいずれかです。`avatar.ground` はアバター自身のマスにあるスタックを `slot` なしの同じ形で並べます。`count` は行が持つ量をネイティブの単位(チャージ式アイテムはチャージ数、それ以外はアイテムの個数)で表し、その行の `pickup` や `drop` が取れる最大量です。`name` はネイティブの一覧と同じ表示名で、色マークアップを含みません。`name` がネイティブの状態マーカーで始まるとき、`durability` がそのマーカーを `{symbol, color}` で示し、クライアントはその色で描けます。どちらの配列も空のときは省略されます。 各行には `label` もあり、ネイティブのリストの言い回しそのままの行です。スタックの表示名に個数と状態マーカーを色マークアップで付け、続けて装備状態 (`(wielded)`、`(worn)`) をプレイヤーの言語で付けます。
- キャラクター画面はテキストではなくネイティブの値と色を公開します。シート(`@`)は種類が `character_sheet` の画面です。`character:tabs` タブ(`stats`、`encumbrance`、`skills`、`traits`、`bionics`、`effects`。表示中のタブは `selected`)の下に、それらを一度に表示する `character:panes` 分割があり、タブごとの `character:<tab>` パネル(`active` は表示中のタブ)が `character:<tab>:rows` リストを持ち、最後に `character:speed` パネルが来ます。行はその原因で名付けられます: `stat:str`、`stat:dex`、`stat:int`、`stat:per`、`stat:height`、`stat:age`、`body:<part>`(まとめた一対は `:pair`)、`skill:<id>` の上の `skill_type:<category>` 見出し、`trait:<id>`、`bionic:<id>`、そして効果です。能力値の行の値は `current` 列(4 つの能力値は `base` も)で、負担の行は `encumbrance`、`layering`、`warmth`、スキルの行は `level`、`exercise` と、該当する場合の `dodge` か `damage` を持ちます。列の `color` は値のネイティブ色名で、特性とバイオニクスの行では行の `color` が名前の色、すべての行はネイティブの文章を `description` に持ちます。バイオニクスのパネルは `power` の stat を持ち、速度の内訳は `character:speed` パネルの stats で、ネイティブの色どおり `good` か `bad` です。このバージョンのシートに習熟タブはありません。`character:tab` はタブを表示し、`character:focus:<tab>` はそのタブの行へカーソルを動かし、行への Enter(`bn:activate:character:focus:<tab>`)はその行へのネイティブの Enter(スキルの訓練の切り替え、能力値の上昇)で、能力値を上げられないときは `CONFIRM` がネイティブの理由を `denial` に持ちます。バイオニクス画面(`p`、種類 `bionics`)は `bionics:panes` 分割で、`bionics:status` パネル(`bionics:help` テキストの上の `power` stat)、`bionics:fuel` テキスト、表示中のタブの `bionics:list` リストを持つ `bionics:tabs` タブ `active` と `passive`(何もなければ `bionics:empty` テキスト)、CBM はカーソルを動かし、行への Enter(`bn:activate:bionics:pick`)はその行へのネイティブの Enter です。`CONFIRM`、`TOGGLE_SAFE_FUEL`、`TOGGLE_AUTO_START` はネイティブのキーが拒むときに `denial` を持ち、`REASSIGN`、`TOGGLE_EXAMINE`、`TOGGLE_SPRITE`、`SORT` - 日記は種類が `diary` の画面で、タイトルは `<name>'s Diary` です。`diary:panes` 分割(`active` はカーソルのあるウィンドウ)は、ページごとの `page:<n>` 行(このセッションの通し番号で、保存されない)の `diary:pages:list` リストを持つ `diary:pages` パネル(`pages: <n>`)、開いたページの見出しと変化の `diary:changes:text` テキストを持つ `diary:changes` パネル、`diary:page:text` テキストを持つ `diary:text` パネル、カーソル下の変化の `diary:info:text` テキストを持つ `diary:info` パネル(`Info`)です。行を渡した `diary:page` と行への Enter はそのページを開き、`CONFIRM` はテキストエディターでページを編集し、`NEW_PAGE` はページを加え、`DELETE PAGE` と `EXPORT_DIARY` はネイティブどおり先に確認します。
- テキストエディター(日記のページのエディター、Lua コンソールのコードエディター。コンテキスト `STRING_EDITOR`)は種類が `text_editor` の画面で、タイトルは `Text` です。`editor:form` フォームは複数行の `editor:text` フィールド(型 `text`)1 つで、`value` がテキスト、`cursor` が文字単位のカーソルです。テキストを渡した `editor:set` はテキスト全体を置き換えてカーソルを末尾に置きます。`TEXT.CONFIRM` は確定し、`TEXT.QUIT` は確定せずに離れます。ネイティブのキーと同じです。
- マップエディタ(プロトコルクライアントが接続している間の `editor` アクション。ネイティブのフロントエンドは従来のマップエディタを開きます)は種類が `editor` の画面(role `screen`)で、タイトルはアクションのラベルです。最初の部分は `editor:file` フォームで、その `path` フィールドは開いているファイルのパスです。テキストを渡した `editor:open` は、ゲームのデータかユーザー MOD の中にある `.json` ファイルのパスを開きます。それ以外のパスでは理由を述べる `editor:notice` テキスト(tone `bad`)が残ります。ファイルを開くと、`editor:body` 分割は次を持ちます。`editor:document` パネル(タイトルはパス。`saved` スタットは `Yes` か `No`、`symbol` スタットは描くシンボル)、ファイルの JSON マップ生成の `editor:objects` リスト(`object:<n>`、n はファイル内の項目の番号、ラベルは `om_terrain` または nested/update の ID。`editor:object` でキャンバスに載せます)、項目の行の `editor:canvas` グリッド(シンボルごとに `square:<x>,<y>` セル、`glyph` がシンボル)を載せた `editor:tools` タブ(`tool:point`、`tool:line`、`tool:rect`、`tool:rect_filled`、`tool:ellipse`、`tool:fill`、`tool:pick`。`editor:tool` で選びます)、`editor:legend` リスト(シンボルごとの `symbol:<s>` 行。割り当てるレイヤーごとに書かれたままの JSON の列を持ち、`description` は由来のパレット。`editor:symbol` で描くシンボルを選びます)、ゲームのローダーがその項目について報告する `editor:diagnostics` リスト(`label` はメッセージ、`description` は指す値の JSON ポインタ)です。セルを渡した `editor:paint` は描きます。鉛筆と塗りつぶしはすぐに、直線、矩形、楕円はアンカー(最初のセル。`selected` かつグリッドの `cursor`)から 2 番目のセルまで描きます。スポイトはセルのシンボルを選びます。描画は 1 回ずつ `editor:undo` と `editor:redo` の 1 ステップです。`editor:save` はファイルを書き、変更のないオブジェクトはバイト単位でそのまま、変更したものはデータフォーマッタの形式で書きます。開いた後にディスク上で変わったファイルには書きません。`QUIT` は離れます。未保存の変更があればはい/いいえで尋ねます。
- 会話は種類が `talk` の画面で、NPC の名前をタイトルにします。`talk:panes` 分割(`active` は `talk:replies`)は、ここまでの会話を項目の間に空行を挟んで持つ `talk:history:text` テキストの `talk:history` パネル(`Dialogue:`)と、`talk:replies` パネル(`Your response:`)です。後者は応答ごとにデータの名前(JSON の応答の `id`、なければトピック id とトピックのデータ内の位置。文や一覧での位置では名付けない)で名付けられ、文字を `hotkey` に、ネイティブの色を持つ行の `talk:responses` リストと、キー `L`、`S`、`Y`、`O` を `hotkey` に持つ `special:look_at`、`special:size_up`、`special:yell`、`special:opinion` の `talk:special` リストを持ちます。応答への Enter(`talk:respond`)はネイティブの確認と判定を経てその応答をし、特別な行への Enter(`talk:special:run`)はそのキーと同じことをします。画面にない行は何も選びません。
- オーバーマップ(`m`、アクション `map`)は種類が `overmap` の画面(role `screen`)で、`map:overmap` マップ(mode `overmap`)と `overmap:toggles` パネルの `overmap` 分割です。パネルの stats は各切り替え(`TOGGLE_MAP_NOTES`、`TOGGLE_BLINKING`、`TOGGLE_OVERLAYS`、...、`SET_CUSTOM_WAYPOINT`)がオンかを示し、オンなら `good` です。マップの `overmap` はネイティブのウィンドウを描かれたまま運びます。`cols`、`rows`、`cells[行][列] = [グリフ, 前景, 背景]`(curses の色インデックス 0〜15: 0 黒、1 赤、2 緑、3 茶、4 青、5 マゼンタ、6 シアン、7 明るい灰、8〜15 は各色の明るい形)、左上のセルのマスを示す `origin`、`player`、サイドバーの文字列 `legend`、表示範囲内の `notes`、色付きの都市と地図の `labels`、`mission_target`、`notes_title`(`LIST_NOTES` の名前)です。ウィンドウはカーソル、つまりマップの `target.current` を中心にし、`target.unit` は `"omt"` で、この画面のすべての位置はマップのマスではなく絶対オーバーマップ地形マスです。`pos` 付きの `overmap:cursor` でカーソルが動き(エンジンの範囲内の任意のマス、階層は -10〜10)、`QUIT` で画面を閉じ、ネイティブのオーバーマップ操作(移動の `CHOOSE_DESTINATION`、`CREATE_NOTE`、`LEVEL_UP`/`LEVEL_DOWN`、各種切り替えなど)は登録アクションです。クライアントは点滅させられないため、オーバーレイ(プレイヤー、メモ、経路)はオーバーレイがオンの間は常時描かれます。`path` は計画された移動経路です。`bn.hello` で `"tiles": true` を伝えたクライアントには `tiles` も届きます。その `cells` はセルごとの `[tile, rotation, subtile]`(ネイティブのタイル表示が選ぶ `overmap_terrain` のタイル ID、90 度回転数、マルチタイルキー)、`looks_like` は各タイル ID のフォールバックです。ほかのクライアントには送られません。セッション中にタイルと ASCII を切り替えるクライアントは、実行中のコマンドがないときに新しい `tiles` の値で `bn.hello` をもう一度送り(実行中なら `command_busy`)、続けて現在のサイズで `bn.viewport` を送ります。これでエンジンは開いている画面を、ID 付きまたは ID なしで再発行します。 `cursor_description` は、ネイティブのサイドバーがカーソルのマスについて述べる翻訳済みの文で、ウィンドウの枠やマスのグリフを含みません。`cursor_here`(カーソルがプレイヤーのマスにあるときの `You are here.`)、`cursor_note`(`Note:` の後に、ネイティブのウィンドウがカーソルのマスのメモについて隅に表示するテキストを続けたもの。例 `Note: cache`)、`route_text`(`path` の長さ。例 `Route of 2 squares.`)はエンジンが作る翻訳済みの行で、当てはまらないときはありません。
- オーバーマップ検索(`SEARCH`、ネイティブの検索欄の後)は種類が `overmap_search` の画面です。`overmap:search` パネルは `search` スタット(検索語)、`result` スタット(`value` は表示中の結果、`max` は結果の数、カーソルに近い順)、`direction` スタット(オーバーマップを開いたマスからの距離と短い方角、例 `3 E`)を持ちます。オーバーマップのカーソルは表示中の結果の上にあり、`NEXT_TAB` と `PREV_TAB` は結果を巡回し、`CONFIRM` はカーソルをそこに残し、`QUIT` はカーソルを戻します。オーバーマップエディタの設置(`PLACE_TERRAIN` または `PLACE_SPECIAL`、設置するものを選ぶ通常のリストの後)は種類が `overmap_editor` の画面で、タイトルは `Place overmap terrain:` または `Place overmap special:` です。`overmap_editor` パネルは `place` スタット(そのラベルと設置する ID の値)、ネイティブの `rotation` 行(`Rotation: ...`、回せなければ `(fixed)`)、ネイティブの `warning` 行(tone `bad`)を持ちます。方向アクションはカーソルを動かし、`ROTATE` は回転できる設置を回し、`CONFIRM` はカーソルの位置に設置して設置を終え、`QUIT` は取り消します。
- 車両ウィンドウ(`^`)は種類が `vehicle_interact` の画面(role `screen`)で、`peers` 分割です。`vehicle:overview` パネルは車両名をタイトルに、ネイティブの stats 行を stats に持ち、その下にカーソルのパーツを囲むマスの `vehicle:grid` グリッド(カーソルが中央)と、カーソルのマスにあるパーツの `vehicle:parts` リスト(`health` 列、壊れていれば赤)があります。作業リスト(取り付け、修理、取り外し、修繕、補給、およびサイフォンや乗員などの選択リスト)では続いて `vehicle:choices` リストが来て、取り付けリストでは `vehicle:tabs` タブの中に入ります。パーツ行は取り付け位置、パーツの種類、その場所の同じパーツの中の順番で名付けられ、リストの位置では名付けられません。隣の `detail` 分割には強調中のパーツの `vehicle:detail` パネルがあります: `time` とパーツの stats、`vehicle:requirements` リスト(出力順に要件の種類ごとの見出し行、要件ごとに満たしているかで色付けした行、その種類がなければネイティブの `NONE`)、`vehicle:description` テキストです。ネイティブのメッセージは `vehicle:message` テキストです。メイン画面ではグリッドがフォーカスで、ネイティブの操作(`INSTALL`、`REPAIR`、...)は拒否されるときネイティブのメッセージを `denial` に持ちます。リストの行を渡した `vehicle:pick` は強調中のパーツなら作業を始め、他のパーツなら強調を移すだけなので、クライアントは先に要件を見せられます。`vehicle:tab` は取り付けタブを id(`all`、`cargo`、`light`、`util`、`hull`、`internal`、`other`、`filter`)で選びます。`QUIT` は一段階戻ります。
- コンピュータ端末はコンピュータ名をタイトルにした、種類が `computer` の画面で、`terminal:output` テキスト(role `terminal_output`)がネイティブウィンドウに表示される端末テキスト(行区切りは `\n`、字下げはそのまま、色を指定しない行は緑)です。任意キー待ち(`context` が `COMPUTER_TERMINAL`)のアフォーダンスは登録アクション `ANY_INPUT`(role `any_key`)で、問い合わせ(`context` が `YESNOQUIT`)では `YES`、`NO`、`QUIT` が対応するキーと同じ応答になります。端末のルートメニューは通常のオプション一覧です。拡張説明(種類 `extended_description`)は、現在の対象を選んだアクションの名前をタイトルにした `description` パネルで、その対象の `description:text` テキストを持ちます。登録アクション `CREATURE`、`FURNITURE`、`TERRAIN` が対象を切り替え、`CONFIRM` と `QUIT` が閉じます。
- ソフトウェアゲーム(スネーク、マインスイーパー、倉庫番、Lights on、robotfindskitten)は種類が`snake`、`minesweeper`、`sokoban`、`lights_on`、`robot_finds_kitten`の画面で、ゲーム名をタイトルにし、`canvas:game`キャンバスが描画されたゲームウィンドウです。`rows`はウィンドウの行ごとの`[text, foreground, background]`のrunの配列(色はオーバーマップと同じcursesの色番号0-15で、行末の空白セルは省略)、`cols`は幅です。ゲームのキーは登録済みアクション(`UP`、`FLAG`、`CONFIRM`、`QUIT`など)で、画面のスコープなので再描画でstaleになることはなく、アクションのないキーは生キー`text`コマンドです。時間で進むゲーム(スネーク)は画面に`refresh_ms`を持ち、ネイティブの入力待ちの長さを表します。その間にコマンドが来なければエンジン自身が待ちを終えてゲームを進め、再描画されたキャンバスを公開するので、クライアントは受け取ったものを描くだけです。robotfindskitten は終了アニメーションを `refresh_ms` 1000 のフレームとして示し、その間キーは何もせず、アクションのないキーである登録アクション `ANY_INPUT`(role `any_key`)を提供します。これは説明画面を抜け、フィールドは無効コマンドの行で応えます。
- 血液検査の結果(血液解析のバイオニクス、オートドック)は種類が `blood_test` の画面で、タイトルは `Blood Test Results` です。`blood_test` パネルは解析が見つけた効果ごとのスタット(`effect:<effect id>`、ラベルはその効果の血液解析の説明、良い効果は tone `good`、それ以外は `bad`)を持ち、なければ `none` スタット `No effects.` 一つだけを持ちます。`CONFIRM` と `QUIT` は画面を閉じます。
- 防衛モードの設定は種類が `defense_setup` の画面(role `screen`)で、タイトルは `DEFENSE MODE` です。`defense` パネルはネイティブの順の 20 個のオプションの `defense:rows` リストを持ち、行は `defense:<option>`(`scenario`、`location`、`initial_difficulty`、`wave_difficulty`、`time_between_waves`、`waves_between_caravans`、`initial_cash`、`cash_per_wave`、`cash_increase`、`zombies`、`specials`、`spiders`、`triffids`、`robots`、`subspace`、`hunger`、`thirst`、`sleep`、`mercenaries`、`allow_save`)と名付けられます。値のオプション(`cash_increase` まで)は見出しをラベルにし、`value` 列とネイティブの説明を持ち、それ以外は `toggled` を持ちます。行を渡した `defense:pick` はネイティブの選択をその行に動かし、行への Enter(`bn:activate:defense:pick`)はネイティブの Enter でトグルを反転します。`LEFT` と `RIGHT` は選択中の値を変えます。`START` は開始し、モンスターグループが一つもオンでなければネイティブの `You must choose at least one monster group!` ポップアップを出します。`QUIT` はありません。
- 防衛モードの隊商は種類が `caravan` の画面(role `screen`)です。カテゴリごとに一つの `caravan:tabs` タブ(`caravan:cart`、`caravan:melee`、`caravan:ranged`、`caravan:ammunition`、`caravan:components`、`caravan:food`、`caravan:clothes`、`caravan:tools`。カートは注文したものを並べる)の下に `caravan:body` の `detail` 分割があります。その `caravan:items` パネルは `cash`、`total`、`left` スタット(合計が所持金を超える間 `left` は `bad`、それ以外は `good`)と `caravan:rows` リストを持ち、リストはカテゴリの商品ごとに `caravan:item:<item type>` と名付けられた行で、`count` と `price` 列(個数 0 なら価格は空、所持金を超えれば赤、それ以外は緑)を持ちます。`caravan:item` パネルは強調中の商品をタイトルにし、その情報を `caravan:details` テキストとして持ちます。フォーカスはネイティブのウィンドウと同じくタブかリストです。タブ ID を渡した `caravan:tab` はそのカテゴリを表示し、行を渡した `caravan:pick` は強調をその行(商品ウィンドウ)に動かし、行への Enter(`bn:activate:caravan:pick`)は `CONFIRM` と同じくネイティブの確認を経てカートを買います。`LEFT` と `RIGHT` は強調中の商品を一つ減らすか増やして注文し、`NEXT_TAB` はタブとリストを切り替え、`HELP` はネイティブのヘルプを表示し、`QUIT` は `Really buy nothing?` と尋ねます。
- エンチャンター(エンチャントするアイテムを選んだ後)は種類が `enchanter` の画面(role `screen`)で、タイトルは `Enchantment Options` です。`enchanter` の `detail` 分割は、アバターがそこで作れるエンチャントごとに `enchant:<enchantment id>` と名付けられた行の `enchanter:options` リストと、強調中のエンチャントのネイティブの情報を折り返さずに持つ `enchanter:details` テキストの `enchanter:info` パネル(`Enchantment Info`)です。行を渡した `enchanter:pick` はネイティブのカーソルをその行に動かし、行への Enter(`bn:activate:enchanter:pick`)は `CONFIRM` と同じくそのエンチャントを選びます(素材が足りないか、アイテムにすでに上限まで適用されていればネイティブのポップアップ)。`PAGE_UP` と `PAGE_DOWN` はネイティブの情報をスクロールし、`QUIT` は離れます。
- Luaコンソールは種類が `lua_console` の画面(role `screen`)で、タイトルは `Lua console` です。`lua_console` 分割は `lua_console:log` テキスト(role `terminal_output`)と `lua_console:input` テキスト(role `terminal_output`)です。ログのテキストは古い順のログ全体で、一行に一項目、ログレベルのネイティブの色で、入力の項目には `>` が付きます。入力のテキストは保留中の入力か表示中の履歴項目です。`EDIT` はネイティブのコードエディタを開き、確定したものを実行します。`HISTORY_UP`、`HISTORY_DOWN`、`LUA_RELOAD`、`TOGGLE_EXPANDED`、`QUIT` は登録されたアクションで、`SCROLL_UP`、`SCROLL_DOWN`、`SCROLL_TOP`、`SCROLL_BOTTOM` はネイティブの表示だけをスクロールします。
- デバッグ NPC 一覧(デバッグメニューの項目)は種類が `debug_npcs` の画面(role `screen`)で、タイトルは `NPCs` です。`debug_npcs` パネルは `overmap` と `local` スタットがネイティブの `Your overmap position:` と `Your local position:` 行で、`debug_npcs:npcs` リスト(オーバーマップ 100 マス以内でアバターに最も近い NPC 20 人、近い順、`npc:<character id>` と名付けられる)と `debug_npcs:monsters` リスト(読み込まれたマップのすべてのモンスター、`monster:<entity id>` と名付けられる)の `debug_npcs:lists` 分割を持ちます。各行は名前をラベルにし、ネイティブの `position` 列をテキストで持ちます。NPC はオーバーマップのマス、モンスターはローカルのマスです。`CONFIRM` と `QUIT` は画面を閉じます。
- ヘルプメニューは種類が `help` の画面で、タイトルは `HELP` です。`help:root` 分割は `help:intro` テキストと、トピックごとの `topic:<n>` 行(`n` はネイティブの順番。キーを `hotkey` に)の `help:topics` リストです。行への Enter(`help:topic`)はそのトピックを `scrollable_text` 画面として開き、`QUIT` はメニューを閉じます。
- ネイティブの長いテキスト(ヘルプのトピック、NPC や派閥のエピローグなど)は種類が `scrollable_text` の画面で、ネイティブのタイトルを持ち、`text:body` テキストが全文です。`UP`、`DOWN`、`PAGE_UP`、`PAGE_DOWN` はネイティブの表示だけをスクロールし、`CONFIRM` と `QUIT` は画面を閉じます。
- メッセージログは種類が `messages` の画面で、タイトルは `Messages` です。`filter` がネイティブのフィルターの `messages` パネルが、選択のない `messages:log` リストを持ちます。リストはフィルターが残すメッセージごとにネイティブの順の `message:<serial>` 行で、行と回数をラベルに、その行をメッセージの種類の色で `markup` に、`time`(どれだけ前か)と `type` 列を持ちます。
- ネイティブの問い合わせポップアップ(はい/いいえなどの選択肢の問い合わせ、キーを押す通知)は種類が `popup` の画面で、独自のビューを持ちません。部品はネイティブのポップアップから作られる汎用のもので、複数あれば `split:root` 分割にまとまります。`text:message` テキストはポップアップの文です。任意キーのポップアップは、キー割り当てファイルの書き方でキー名を受け取り(`bn:fill:form:field`)そのキーを押す型 `key` の `field:key` フィールド(ラベルなし。キーの用途はメッセージが述べる)の `form:field` フォームと、`bn:any_key` アフォーダンスを持ちます。`list:choices` リストは選択肢ごとにアクションの名前をラベルにした `option:<action>` 行(同じアクションの n 番目は `#<n>`)、選択肢のないポップアップでは `acknowledge` 行 `OK` 1 つを持ち、行への Enter(`bn:choose:list:choices`)はそれで答えます。取り消せるポップアップは `bn:cancel` を持ちます。
- ゾーンマネージャーは種類が `zones` の画面で、ネイティブのウィンドウと同じくサイドバーの上に `overlapping` で置かれます。分割の中に `zones:list` パネル(タイトル `Zones`、ゾーンがなければ `No Zones defined.` の stat)とその中の `zones:rows` リストがあります。行はゾーンごとに一つで、種類と範囲で名付けられ(`zone:<type>:<start>:<end>`、前に同じものが n 個あれば `#<n>`)、有効なら `toggled` で、`type`、`distance`、`direction`、`vehicle` の列を持ちます。続いて強調中ゾーンのオプションの `zones:options` パネルと、`SHOW_ALL_ZONES`、`TOGGLE_ZONE_OVERLAY`、`debug_submap_grid` の `zones:display` リスト(オンなら `toggled`)が来ます。行を渡した `zones:pick` はネイティブのカーソルをそこへ動かし、`zones:toggle` は表示行を切り替えます。ゾーンの操作は登録済みの操作で、ネイティブのキーが何もしないとき(ゾーンがないときのゾーン操作、ゾーンが 2 つ未満での移動)は `denial` を持ちます。ゾーンの範囲選択(追加、位置の編集、位置の移動)は `look` 画面です: `target.status` は `zone_first`、`zone_second`、`zone_move`(それ以外は `look`)で、`target:move` か方向操作でカーソルを動かし、`CONFIRM` でマスを決めます。マップエディタは種類が `editmap` の画面で、`look` と同じターゲット画面で `target.status` は `editmap` です: カーソルが編集するマスで読み込まれたマップの中に制限され、`target` パネルの `show_all` stat がマップ全体を表示しているかを示し、マスの部分は地形、家具、フィールド、罠、クリーチャーか車両、アイテムとその id・数値で、編集操作(`EDIT_TERRAIN`、`EDIT_FURNITURE`、`EDIT_TRAPS`、`EDIT_FIELDS`、`EDIT_ITEMS`、`EDIT_MONSTER`、`EDIT_OVERMAP`、`EDITMAP_SHOW_ALL`、`LEVEL_UP`、`LEVEL_DOWN`)は登録済みの操作です。編集メニューは通常のリストで、`QUIT` でエディタを出ます。形状選択(種類 `editmap_shape`、`target.status` が `editmap_shape_resize` か `editmap_shape_move`)と mapgen の対象変更(種類 `editmap_mapgen`、`target.status` が `editmap_retarget`)も同じ形のターゲット画面で、`target:move` がカーソルを(移動中は選択も)動かし、`RESIZE`、`SWAP`、`EDITMAP_MOVE`、`START`、`EDITMAP_SHOW_ALL`、`CONFIRM` は登録済みの操作です。`target.marks` はネイティブのエディターが強調するマスです。編集が適用される `selection` は `squares` で、マップ生成の画面では対象のオーバーマップ地形マスの `omt_border` が `rect` で、マップ生成のプレビュー中はネイティブ表示がその周りの角に印を付ける `stamp` が `rect` で来ます。マップ生成の一覧が上に開いている間もエディター画面はこれを保ち、クライアントはアバターの記憶を変えずにマップの上に描きます。
- 設定画面はネイティブのものです。メインメニューの `settings:options`、`settings:keybindings`、`settings:autopickup`、`settings:safemode`、`settings:distractions`、`settings:colors` の行から開きます(オプションとキー割り当てはゲーム中も開けます)。オプション(種類 `options`、role `screen`): `options:pages` タブはページごとに ID で一つずつで(`general`、`interface`、`graphics`、...、`world_default`。ゲーム中は `Current world` と表示。ワールド自身のオプションはタブのない 1 ページでタイトル `World options`)、その下の `options:body` detail 分割に `options:items` リストとカーソル行の `options:detail` パネルがあります。リストには `group:<id>` 行(開いていれば `toggled`)と、`value` 列、グループを指す `parent_id`、前提条件を満たさないときの `denial` を持つ `option:<NAME>` 行があります。パネルは `options:tooltip` テキスト、ゲーム中のワールドのページでは `options:note` テキスト、設定できるオプションなら `options:editor` フォームを持ちます。フォームの 1 つのフィールドは行で名付けられ、`bool`(`true`/`false`)、`select`(`options[].id` のいずれか)、`integer`/`float`(`min`〜`max`)、`text`(`max_length` 以下)です。その行とテキストを渡した `options:set` がオプションを設定し、フィールドが提供しない値はエンジンが拒否します。`options:page` はページを表示し、`options:select` はカーソルを動かし、`options:activate` は行への Enter です。`QUIT` で抜けるとネイティブの「変更を保存しますか?」が出て、保存すると適用され書き込まれます。キー割り当て(種類 `keybindings`): `keybindings:window` パネル(通常表示以外では `mode` stat、`filter`)の下に `keybindings:legend` テキストと `keybindings:actions` リストがあり、アクションごとに `keys` と `scope`(`Unbound`、`Local`、`Global`)の列をネイティブの色で持つ `action:<ID>` 行があります。登録アクション `ADD_LOCAL`、`ADD_GLOBAL`、`REMOVE`(ネイティブが提供する場合は `EXECUTE`)が次の行への `keybindings:pick` の動作を決め、テキストを渡した `keybindings:filter` は通常表示で名前によりアクションを絞り込み、新しいキーの入力は `key` 型のフィールドで、キー割り当てファイルと同じ綴り(`z`、`=`、`F9`、`CTRL+A`)のキー名を受け取ります。自動拾い(種類 `auto_pickup`)とセーフモード(種類 `safemode`)、どちらも role `screen`: `global` と `character` のタブ(`autopickup:tabs`、`safemode:tabs`)の下に、ルールごとの `rule:<n>` 行(空のルールは `<empty rule>`)が `i_e` と `active` の列、または `attitude`、`dist`、`whitelist`、`category`、`active` の列を持ち、隣の詳細パネルは有効化オプションを stat に、その下にパターンのヘルプを持ちます。`autopickup:edit` と `autopickup:mode` はルールの文字列と I/E を、`safemode:edit`、`safemode:attitude`、`safemode:dist`、`safemode:list`、`safemode:category` は対応する列を、その列への Enter と同じく編集します。ルール操作(追加・削除・移動・テストなど)は画面の登録済みアクションで、対象のルールがないときは `denial` を持ち、ルールをテストするとそのルールに合うアイテムかモンスターを並べるダイアログ(`auto_pickup_test`、`safemode_test`)が開きます。注意散漫(種類 `distraction_manager`): 注意散漫ごとの `distraction:<name>` 行があり、`status` が `Enabled` なら `toggled` で、隣に `distractions:description` テキストがあります。`distractions:toggle`(Enter)が切り替えます。色(種類 `colors`): `colors:columns` タブ `normal` と `invert` の下に `colors:items` リストがあり、色ごとに `normal`、`normal_custom`、`invert`、`invert_custom` 列を持つ `color:<name>` 行があって、`colors:detail` パネルは `colors:note` テキストと、表示中の列のカスタム色を選ぶ `select` フィールド 1 つの `colors:editor` フォームを持ちます。色名を渡した `colors:set` がその色を設定し、`colors:activate`(Enter)はネイティブの色リストを開きます。
- 自動メモ管理は種類が `auto_notes` の画面(role `screen`)で、タイトルはネイティブの前後の空白つきの `AUTO NOTES MANAGER` です。`autonote:body` `detail` 分割は、見つけたマップ特殊地形ごとの `extra:<map extra id>` 行(`symbol`(マップでの色)と `enabled` 列、メモが有効な間は `toggled`)の `autonote:extras` リストと、`autonote:status` パネルで、パネルの `enabled` スタット `Auto notes enabled:` は `AUTO_NOTES` オプションが有効な間は `good`、それ以外は `bad` です。何も見つけていなければ `autonote:notice` テキストが続き、行のアフォーダンスはありません。`autonote:select` はカーソルを動かし、行への Enter(`autonote:toggle`)は `CONFIRM` と同じくそのメモを切り替えます。`ENABLE_MAPEXTRA_NOTE`、`DISABLE_MAPEXTRA_NOTE`、`SWITCH_AUTO_NOTE_OPTION` は登録されたアクションで、メモが変わっていれば `QUIT` はネイティブの `Save changes?` を尋ねます。
- `avatar.sidebar` は同じ getter から取ったネイティブのクラシックサイドバーの値と、そのパネルが表示するラベルです。配置と描画はクライアントが行います。文字列の値は `{label, text, color}` で、`label` は翻訳されたパネルのラベル(パネルが表示しない場合は無し)、`color` は色に意味がある場合のネイティブ色名です。メンバーは `limbs`(`id`、`label` と状態色、`hp`、`hp_max`、体力の `color`、`broken`)、`pain`、`hunger`、`thirst`、`fatigue`、`temperature`、`power`、`location`、`weather`(地下ではラベル無し)、`focus`(`label`、`value`)、`morale`(`level`、ネイティブの `face`)、`stamina`(`label`、`current`、`max`、`color`)、`speed`(`label`、`value`、`color`)、`movement`(`counter`、`mode` は `walk`、`run`、`crouch`、`prone`、翻訳された1文字の `mode_text`)、`safe_mode`(`label`、`enabled`、`color`)、`time`(`season`、`day_label`、`day`、`clock`: 時計の時刻、なければおおよその時間帯、地下ではネイティブの時刻不明の文言)、任意の `ambient_temperature`(温度計がある場合のみ)、`weapon`、任意の `style`(武術スタイル)です。手足の体力とスタミナはバーではなく数値で、クライアントが自分の形で描きます。文字列はエンジンの表示言語で、それ以外の値は言語中立です。`stats` の項目はネイティブの `color` を持つことがあり、4つの能力値はサイドバーの `short_label` も持ちます。
- 地形ウィンドウはネイティブのウィンドウサイズ変更と同じ方法で決まります。`bn.hello` の `viewport = {cols, rows}`(マップのマス 1〜512)、または後の `bn.viewport` は、端末をそのマス数にサイドパネルを足した大きさへ変え、エンジンがアバター周辺をその分だけ映すようにします。ネイティブの最小端末サイズが引き続き適用されるため、実際の `view` が正です。何も送らなければ既定の端末が使われます。
- すべてのイベントは汎用の `changes` ブロックを持ち、`coverage`、`view`、`cells`、`forgotten`、`entities`、`gone` の順に適用した後、`avatar`、`environment`、`route`、`interaction` を置き換えます。
- バイト数を減らすため、セルレイヤーの `look` はレイヤーが既に示している `kind` を省略し（`terrain`、`furniture`、`trap`、`field`、`item`、`vehicle_part`。`memory.terrain` は `terrain`、`memory.overlay` は自身の値を保持）、`subtile` が `center`（形を持つレイヤーの既定値）のとき省略し、すべての `look` は `rotation` が 0 のとき省略します。イベントの `interaction` は `actions` が直前の境界と同じとき省略します。クライアントは自分の値を保持し、空のリストはそれを置き換え、スナップショットは常に一覧を含みます。
- イベントの `avatar` は、直前の avatar と同じで空でないメンバーを省略し、`keep` に名前を挙げます ("look"、"overlays"、"traits"、"stats"、"inventory"、"sidebar"、"ground")。クライアントは自分の値を保持し、それ以外で無いメンバーは空です。スナップショットの avatar は常に完全です。
- `message.logged` はネイティブのメッセージログです。`data = {id, text, kind, color, count, turn}` で、1 行ごとに 1 イベントがログの順に、原因となったコマンドに紐づいて送られます。`text` は色タグと「x N」を除いた翻訳済みの行、`kind` はネイティブの種別(`good`、`bad`、`mixed`、`warning`、`info`、`neutral`、`debug`)、`color` はその種別のネイティブの色名です。最後の行が繰り返されると、同じ `id` が高い `count` で再度送られ、その行を置き換えます。状態は変えず(`revision` は進みません)、他の一時イベントと同様 `bn.resync` をまたぐと失われます。ただしログ自体は失われません。`bn.subscribe` が最新 100 行を `messages`(古い行から、`data` と同じ形、空なら省略)として返すので、ロードや resync の後に購読するクライアントも、ネイティブのクライアントが表示するログから始められます。以後の `message.logged` イベントをこの一覧に適用すると(繰り返しは同じ `id` の行を置き換え、100 行を超えると最も古い行が外れます)、新しく購読して得られる一覧と一致します。ネイティブのログがクールダウンで隠すメッセージは送られません。 `label` はネイティブのログが表示するそのままの行で、`count` が2以上なら `text` の後に翻訳済みの繰り返し接尾辞 (`x 2`) が付きます。`turn` はその行が記録された、または最後に繰り返されたゲームターンで、クライアントはこれでターンを区切って表示できます。翻訳可能な書式から作った行は `text` が LocalisedString(`{key, ctx?, plural?, plural_key?, args?, npcname?}`: msgid、その文脈、複数形を選ぶ個数、複数形の msgid、順に並んだプレースホルダーの値、値を埋めた後に各 `<npcname>` が指すもの)で、クライアントはエンジンのカタログで自分の言語に訳します。その中の名前(モンスターの名前など)はそれ自体が LocalisedString で、どのカタログも訳さない key は `plural` が 1 以外なら `plural_key` として読みます。NPC やモンスターについての行には `npcname` があります: NPC の名前、またはモンスターの `the %s` の LocalisedString です。スナップショットはそのカタログを `catalogues` で示します。エンジンのマシン上にある接続の言語のファイルで、基本ゲームのもの、次に有効な MOD のものが検索順に並びます(前のファイルの項目が優先し、後のファイルだけに複数形がある場合は後のファイルが優先)。カタログのない言語では省略します。
- `projectile.moved`、`explosion.started`、`explosion.blast`、`explosion.ended`、`combat_text.shown` はネイティブのアニメーション事実です。ゲームがアニメーションを始める箇所で公開されるため、どのクライアントもレンダラーなしで同じ事実を得ます。状態は変えず、原因のコマンドに紐づき、そのコマンドの状態イベントより前に届きます。`display.duration_ms` はネイティブのアニメーションがその事実を保持する時間です(1 ステップあたり `ANIMATION_DELAY` オプション)。`projectile.moved` は `path`(描画順のマス。弾が飛ぶ間はイベントごとに 1 マス)と、グリフとカスタムスプライト ID を持つ種別 `projectile` の `look` を持ちます。`explosion.started` は `at`、`radius`、`color` と、ネイティブのタイルが使うタイル ID `tile` を持ちます。描画するかどうかはクライアントが決めるため、`ANIMATIONS` オプションはこれらを抑止しません(クライアントはゲームを変えません)。戦闘テキストだけは `ANIMATION_SCT` が必要です。`explosion.blast` は地形で形が変わる爆発の 1 リング分の `cells` を並べます。カスタム爆発 (EMP、スクランブラー、呪文) は範囲全体を一度に並べ、同じ順で各マスのネイティブ色名を `colors` に入れます。`combat_text.shown` は `at` に出る 1〜2 色の `segments` の浮遊テキストで、ネイティブと同じく 1 アニメーションステップごとに `scroll`(単位ステップ)だけ動きます。`kind` が `hp` のものはクリーチャーの HP 表示で、その横に留まります。
- 投げられたアイテムはゲームイベントとしても公開され、アニメーションのオプションでは止まりません。どれもアバターに見えるものだけが公開されます。`item.activated`(`at`、`look`、導火線の残りターン数 `turns`)は導火線に火がついたときと、燃えている間の毎ターンに出ます。`item.thrown`(`projectile`、`look`、`by`、`from`、`to`)が飛行の始まりで、その `projectile.moved` イベントは同じ `projectile` を持ち、`item.landed`(`at`、`look`、攻撃が放った場合は `projectile`)が終わりです。投げられた弾や撃たれた弾は `projectile.hit`(`at`、アバターに見えるクリーチャーに当たった場合は `entity`。障害物なら無し)にも同じ `projectile` を持ち、これは `projectile.moved` の後、それが起こした `entity.damaged` や地形の変化の前に来ます。1回の多弾射撃(散弾など)の弾は1発ずつ順に飛び、それぞれ自分の `projectile` を持ち、イベントもその順に来ます。それらの `projectile.moved`、`projectile.hit`、`item.landed` は同じ `group` を持つので、クライアントはネイティブのゲームのように弾をまとめて表示できます。爆発は `explosion.started`、論理時間ステップごとの `explosion.blast` または `explosion.shrapnel` のリングとそのステップが起こしたこと、そして `explosion.ended` です。起こしたこととは、クリーチャーが受けた攻撃ごとの `entity.damaged`(`id`、`amount`、キャラクターなら `part`)、ステップで変わったマスの `terrain.changed` と `furniture.changed`(`at`、`from` と `to` の look)、追加または除去されたフィールドごとの `field.changed`(`at`、`field`、変化後の `intensity`。消えたら 0)です。`entity.damaged` はクリーチャーが受けるすべてのダメージ(直接加えられたものを含む)で出ます。地形・家具・フィールドの変化は爆発に限らず、ゲームが起こすたびに公開されます。アバターに見えるマスを変えるすべての呼び出し(ドアを壊す、家具を置く、フィールドを足す・除く)は共有のマップ境界で、フィールドターン(延焼、ガスの拡散、フィールドの減衰。スキップしたターンも含む)はアバターの階で見えるフィールドの前後を比べて、違うマスごとに 1 件の `field.changed` として公開されます。長い待機のあとでも、そのマスは 1 回だけ伝えられます。
- `sound.heard`(`text`、`volume`、`marker`、`logged`)は、ネイティブの聴覚ルール(周囲の騒音に対する音量、聴覚保護、睡眠、難聴)を通ってアバターに届いた音です。`text` はネイティブのメッセージが挙げる説明、`volume` はアバターに聞こえるデシベル、`marker` はネイティブのゲームが音を示すマスです。マーカーは音源ではなく、その近くでアバターから見えないマスで、アバターが音源にいるか音源が見えるときは省かれるため、隠れた音源は漏れません。音のログ行はネイティブのメッセージルールとクールダウンに従いますが、`sound.heard` は足音などログが省く音も含め、聞こえたすべての音について公開されます。`logged` は、その音がメッセージログにも行を持つとき `true` で、両方を表示するクライアントが同じ音を一度だけ挙げられます。 アバター自身の叫びは、そのアクションが自分で行 (`You yell ...`) を記録するため logged として扱います。
- `sound.played`、`sound.channel`、`music.changed` は、エンジン自身が音を鳴らすかどうかにかかわらず、ネイティブのサウンドプレイヤーが受け取る再生の依頼です。クライアントは hello が `engine.sound.soundpack` として示すフォルダのサウンドパック(`SOUND_ENABLED` オプションがオフの間は省略)から、ネイティブのプレイヤーと同じやり方で鳴らします。`sound.played`(`id`、`variant`、`volume`、`angle`、`stacks`、`wait_ms`)はパックの `sound_effect` 一つです。そのバリアントがないパックは効果の `default` バリアントを鳴らし、効果の `files` から一つを無作為に選び、`stacks` が `false` なら同じ音がまだ鳴っている間は飛ばします。`wait_ms` のある音(足音、障害物、銃声)は、`wait_ms` のある最後の音が鳴ってからそのミリ秒が過ぎたときだけ鳴り、鳴ると待ちが始まり直します。`sound.channel`(`channel`、`id`、`variant`、`volume`、`gain`、`angle`、`loops`、`fade_ms`)は予約チャンネル(環境音、天候、危険テーマ、エンジン、ラジオ)が今鳴らすものです。新しい音は `fade_ms` のフェードインで始まり、同じ `id` と `variant` は新しい `gain`(音量の変更で、オプションやパックの音量を掛けないミキサー単位)や `angle` で鳴り続け、`id` のないチャンネルは `fade_ms` かけてフェードアウトします。チャンネル `any` はすべてのチャンネルと効果音をフェードアウトします。最初のストリームは、すでに鳴っているチャンネルと音楽から始まります。新しい `epoch` のストリームは、前のストリームが伝えたものから続きます。止まるまで繰り返さない音(`loops` が 0 以上)をまだ鳴らしているチャンネルは、新しい開始を無視します。`music.changed`(`playlist`、`volume`)は鳴らすパックのプレイリストを示し、プレイリストの指定どおり順番にまたはシャッフルして鳴らします。`playlist` がなければ音楽は止まります。`volume` はネイティブの `SOUND_EFFECT_VOLUME`、`AMBIENT_SOUND_VOLUME`、`MUSIC_VOLUME` オプションを適用したミキサー単位(128 が最大ゲイン)で、効果やプレイリスト項目にパックが定める `volume`(0-100)がこれに掛かります。`angle` はネイティブのミキサーが音を置く方向で、正面から時計回りの角度(90 が右)です。サウンドなしでビルドしたエンジン(`SOUND=OFF`)はこれらを一つも公開しません。
- `entity.moved`(`id`、`to`、`from`、`mode`)と `entity.gone`(`id`、`reason`)により、クライアントはスナップショットが開示するモンスターと NPC を、再同期なしでアクションの間じゅう追えます。`entity.moved` はアバターに見えるクリーチャーの移動ごとに、移動先のマスで公開されます。移動元のマスがアバターに見えていなければ `from` は省かれ、`mode` は隣のマスへの一歩なら `walk`、それより長い移動(押される、テレポート)なら `propelled` です。アバター自身の移動は状態の差分に含まれます。`entity.gone` は、クライアントが知っていたクリーチャーがもう開示されないことを示し、`reason` は `lost_sight`(視界から出た、またはアバターや視点が動いた)、`died`、`removed`(ゲームから消えた)です。視界から歩き出たクリーチャーはその場で `gone` になり、それ以外は境界の公開時に見つかります。混んだターンでは `entity.moved`、`terrain.changed`、`furniture.changed`、`field.changed` の最初の 256 件だけが公開されます(視界から歩き出たクリーチャーの `gone` も数えます)。境界の `cells.seen` 変更セットは常に最終状態を持つため、イベントは順序とタイミングを加えるだけで、状態を置き換えることはありません。

イベントは `interaction.changed`、`coverage.moved`、`turn.passed`、`cells.seen`、`message.logged` と上記のアニメーション事実で、今後スキーマに挙げた残りの演出タイプが加わります。0.2 の公開前に追加したイベントタイプは 0.2 に含まれ、公開後は新しいイベントタイプに新しい正確なバージョンが必要です。
