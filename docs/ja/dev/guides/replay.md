title: 入力の記録とリプレイ
---

`--replay-record PATH` でゲームセッションを記録し、`--replay-play PATH` で再生します。これらのオプションは共有入力境界を使うため、タイル、Curses、MCP で動作します。再生は入力を直接供給するので、MCP の記録を再生するときに MCP ホストは不要です。

```sh
out/build/linux-full/src/cataclysm-bn --client=tiles \
  --userdir out/record-user/ --configdir out/record-user/config/ \
  --seed example --replay-record out/example.jsonl
out/build/linux-full/src/cataclysm-bn --client=tiles \
  --userdir out/playback-user/ --configdir out/playback-user/config/ \
  --replay-play out/example.jsonl
```

**両方の実行を、同一の初期ユーザーディレクトリのコピーから開始してください。** `--userdir` と `--configdir` の両方を渡してください。そうしなければ、XDG ビルドはアカウントの通常設定を引き続き使用します。実行前に、同じコマンドへ `--paths` を追加して解決されたパスを確認してください。リプレイは入力の記録であり、セーブのスナップショットではありません。ワールド、設定、キーバインド、キャラクターテンプレート、Mod データは復元しません。通常のセーブを対象にリプレイしないでください。特に、プレイした _後で_ 記録用プロファイルをコピーしても初期状態は再現されません。

同じゲームビルド、ゲームデータ、Mod、オプション、クライアント、初期端末サイズを使ってください。ヘッダーが記録時の RNG シードを提供し、再生時に明示的な `--seed` を指定する場合は一致しなければなりません。二つのリプレイオプションは同時に使えません。記録時に既存ファイルを上書きすることはありません。

## 記録される内容

バージョン付き JSONL ストリームには次のものが含まれます。

- 形式バージョンと決定的 RNG シードを持つヘッダー。
- キーボード、テキスト/IME、マウス、ゲームパッド、セマンティックインタラクション、時間制限付きポーリング、空ポーリングの各イベントと、その入力コンテキスト、登録済みアクション、ポーリングのタイムアウト。空の非ブロッキングポーリングも重要です。省略すると、活動中に後の入力が早すぎる時点で適用される可能性があります。
- 入力数を持つ正常終了レコード。

イベントは既存のゲーム入力ロジックを通ります。ターン単位のアクションだけでなく、ネストしたプロンプトも記録されます。記録中と再生中は、実時間ではなく各シミュレーション呼び出し境界で中断可能な活動をポーリングします。これにより両方のリプレイモードで空ポーリングの順序が一致し、通常プレイでは 100 ms のポーリング制限が維持されます。再生は正常終了レコードで停止し、人間の入力を待たず正常終了します。セーブするには、記録内にゲーム内セーブアクションが必要です。

セマンティックレコードは、操作、不透明な選択肢/フィールド/候補 ID、項目数、対象位置を保持しますが、転送要求番号に似た `input_id` は保持しません。再生時には同じウィジェット実装へ渡し、適用前にインタラクションの種類、スキーマ、数量制約、対象の同一性と射程を検証します。これによりクライアント間の再生を可能にしつつ、並べ替えられた所持品、変更された対象、または同じ汎用入力コンテキストにある別の一覧が操作を黙って消費することを防ぎます。

コンテキスト不一致、インタラクションスキーマ不一致、不明な形式バージョン、不正なイベント、矛盾する件数、終了レコードの欠落はエラーです。診断にはファイルとレコード行が示されます。記録済み入力を消費する前にゲームが終了した場合も失敗します。再生は記録全体をメモリへ読み込まず、一度に一レコードずつ読み取ります。

決定的 RNG サポートは、通常の並列処理を維持しながら、キー付きワーカータスクと並列ループのインデックスに独立した乱数ストリームを与えます。異なるゲームバージョン、プラットフォーム、標準ライブラリ、CPU/GPU 計算ポリシー、またはすべての非同期ゲームシステムで同じ結果になるという保証ではありません。入力コンテキストの検証はインタラクションのずれを検出しますが、シミュレーション状態全体のチェックサムではありません。

## 実セッションのスモーク検査

Linux では、`MCP=ON` のビルドに対して標準ライブラリだけを使うスモークドライバーを実行します。

```sh
python3 tools/client/replay_smoke.py --binary out/build/linux-clients/src/cataclysm-bn --output out/replay-smoke-1
```

出力ディレクトリは事前に存在していてはいけません。ドライバーは同一の初期プロファイルを作成し、MCP を通じてチュートリアルセッションを記録します。待機によってチュートリアルの所持品が空になる前に、公開された空でない所持品セレクターで正確な数量を設定し、共通の照準 UI に入ってカーソルを動かします。次に、見えている位置と通行可能性を使ってバックパックを取得・着用し、地面の拾得モデルでマチェーテを選択し、ネイティブの解体メニューでカーゴパンツを再利用して、生成された布を拾い、活動状態を観察して非ブロッキングポーリングでのみ `IDLE` を送り、簡易包帯 2 個のバッチ製作を完了します。さらに、製作と建設の拒否検査、待機、東西への移動、所持品フィルター、セーブも維持します。MCP ホストなしで再生し、保存された JSON 全体を比較します。起動時の選択肢、チュートリアルダイアログ、所持品の項目とフィールド、照準、確認にはライブのセマンティック記述を使い、通常のゲームプレイ移動には検出したアクションを使います。同期に端末スクレイピング、固定入力回数、固定遅延は使いません。

成果物には、両方の `--paths` 事前検査結果、入力記録、プロトコル要求/応答とタイミング、stderr ログ、両方のプロファイル/セーブ、バイナリと記録のハッシュ、`summary.json` が含まれます。短いシナリオの成功はそのシナリオの証拠であり、すべてのゲームプレイで決定的リプレイが可能だという証明ではありません。
