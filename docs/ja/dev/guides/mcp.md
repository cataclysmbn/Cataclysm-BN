---
title: MCP を通じてプレイする
---

BN MCP クライアントを使うと、エージェントが既存の画面と操作を通じてゲームを実行できます。キャラクター作成、ワールド選択、所持品、製作、照準、会話、セーブには、対話型クライアントと同じゲームコードが使われます。

`linux-clients` プリセットを使うか、[CMake の設定](building/cmake.md)時に `MCP=ON` を有効にしてから、`cataclysm-bn` ターゲットをビルドしてください。タイルや curses と同時に有効化でき、三つとも同じエンジンビルドを使います。共有バイナリを起動するときは `--client=mcp` でクライアントを明示的に選択してください。

## 接続

MCP ホストが stdio 転送で実行ファイルを起動するよう設定してください。実行ファイル、データディレクトリ、プロファイルには絶対パスを使ってください。次の例のパスをチェックアウトとビルド出力に合わせて変更します。

`linux-clients` プリセットを使う場合、標準のバイナリパスは `out/build/linux-clients/src/cataclysm-bn` です。

```json
{
  "mcpServers": {
    "bn": {
      "command": "/path/to/Cataclysm-BN/out/build/linux-clients/src/cataclysm-bn",
      "args": [
        "--client=mcp",
        "--datadir",
        "/path/to/Cataclysm-BN/data/",
        "--userdir",
        "/path/to/bn-agent-profile/",
        "--configdir",
        "/path/to/bn-agent-profile/config/"
      ]
    }
  }
}
```

選択したプロファイルには、設定、ワールド、セーブ、キャラクターテンプレートが含まれます。二つのディレクトリオプションを必ず両方渡してください。XDG ビルドでは `--userdir` だけを指定しても、アカウントの通常設定を読み書きする可能性があります。接続前に一度 `--paths` を追加して実行し、`Config Directory` がプロファイル内のパスとして解決されることを確認してください。通常のゲーム起動経路でワールドを読み込むには `--world NAME` を追加します。それ以外の場合は、開始メニューでワールドとキャラクターを作成または選択してください。

転送には [MCP stdio](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#stdio) を使います。stdin と stdout 上の改行区切り JSON-RPC です。各入力フレームは終端の改行より前で最大 1 MiB です。大きすぎるフレーム、終端されていないフレーム、読み取れないフレームはセッションを 0 以外の終了ステータスで閉じ、拒否されたフレームの接頭部は実行しません。ゲームの診断は stderr に出力されます。MCP クライアントはゲーム出力をリダイレクトする前に元の stdout を複製するため、Lua やエンジンコードが診断を出力しても、プロトコルの stdout は有効な JSON-RPC のままです。端末ウィンドウは不要です。

## プレイ

| ツール           | 用途                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------- |
| `bn.observe`     | 現在の合成画面を読み取ります。                                                          |
| `bn.state`       | プレイヤーに見える、または既知の構造化されたゲーム状態を読み取ります。                  |
| `bn.actions`     | アクティブなコンテキスト、アクション名、実際のキーバインドを取得します。                |
| `bn.press`       | 通常の入力パイプラインを通じてキーまたは登録済みアクションを送ります。                  |
| `bn.interaction` | 画面を解釈せず、ライブの構造化された選択肢またはテキスト/数値フィールドを読み取ります。 |
| `bn.interact`    | セマンティックな選択、フィールド、数量、対象、キャンセル操作を適用します。              |

`bn://screen` リソースも画面を公開します。`rows` には UTF-8 テキストが含まれ、`styles` は前景色/背景色を `[start_cell, length, foreground, background]` の連続区間として保持します。セルのインデックスは左から右、次に上から下へ進みます。座標は端末セルで、全角文字は二つのセルを占めます。カーソル座標はテキスト入力と選択位置を示します。

`bn://state` リソースと `bn.state` ツールは、アバター、実行中の活動とその ID、欲求、部位ごとの HP、所持品とネストした内容物、着用/装備中の品、見えているマップの地形/家具/通行可能性/クリーチャー/アイテム、既知のオーバーマップ地形を報告します。開始メニューとキャラクター作成中は `game_ready` が false で、ワールドとアバターの設定完了後にだけ true になります。既定の状態ビューは可視マップ半径 12 セルと既知オーバーマップ半径 8 OMT を対象とし、応答の `coverage` にこの範囲が含まれます。可視性検査では、見えないクリーチャーと見えない地形の背後にあるアイテムを除外します。地面のアイテムは外側だけを公開し、所有する所持品と装備ではネストした内容物も含めます。アバターと可視マップの位置はリアリティバブルのマップスクエアを使い、`avatar.absolute_position` はバブルが移動しても安定しています。既知のオーバーマップ位置は絶対オーバーマップタイルを使います。`dimension` は現在の次元を示します。

`structured` が true の場合は `bn.interaction` を優先してください。選択肢の記述には、不透明 ID、ラベル、説明、拒否理由、実際の有効状態、最終的な選択可否、`selected`、`highlighted` が含まれます。`selected` は確定済みの選択状態を表し、`highlighted` は現在のナビゲーションフォーカスを表します。通常の単一選択メニューでは、現在行が両方のフィールドに反映されます。所持品の複数選択では、選択数が 0 より大きい場合にだけ `selected` が true になります。単一項目ピッカーの表示中は確定済みの選択がないため、フォーカス行は `choose` でピッカーを閉じるまで `highlighted` だけが true です。数量を扱う選択肢には `selected_count`、省略可能な `minimum_count`、`available_count` も含まれ、`minimum_count` の省略は 0 を意味します。所持品行では、`label` と `columns` は選択画面の行に対応し、`description` には通常の `EXAMINE` アクションで表示される詳細なアイテム情報が入ります。完全なゲーム内表示には引き続きこのアクションを利用できます。フィールドの記述には、現在値、テキストまたは整数の型、最大表示幅、印字可能文字の制約が含まれます。対象の記述には、リアリティバブルのマップスクエアで表した起点とカーソル、射程、距離規則、境界、状態、見えている候補が含まれます。選択肢ページは既定で 100 項目で、`offset` と `limit` を受け取ります。`choice_page.offset` と `choice_page.total` は、返された位置と全項目数を報告します。二つのペインを持つビューは、不透明なペイン ID とエリア ID、ビュー固有の役割（`source`、`destination`、`npc`、`player`）、エリアのラベルと説明、フィルター、明示的な `storage_kind`（`inventory`、`worn`、`container`、`ground`、`cargo`、`mixed` のいずれか）を含む `panes` も公開します。各選択肢は `pane_id`、アイテムの実際の `area_id`、そのアイテム自身の `storage_kind` で対応するペイン、エリア、保管場所を参照します。

すべての `bn.interact` 要求は、現在の `input_id` と正確に一つの操作を指定します。`choose` はスナップショットの `choice_id` を取り、`fill` は `field_id`、`value`、明示的な `submit` 真偽値を取ります。`set_count` は `choice_id` と 0 以上の `count`、`set_target` は整数の `x`、`y`、`z` を持つ `position` と、任意の公開済み `candidate_id` を取ります。`cancel` にはペイロードがありません。数量 0 は所持品項目の選択を解除しますが、公開された `minimum_count` が正の数量を要求する場合があります。応答は操作が消費されるまで保留され、次の安定したインタラクションスナップショットを返します。古い境界、変更されたスキーマや対象の同一性、不明な ID、無効な選択肢、不正なフィールド、利用できない数量、射程外または境界外の対象は、部分的な変更を行わず拒否されます。

起動時のルート/サブメニュー、`uilist`、通常の選択/確認/通知ポップアップ、`string_input_popup` のテキスト/数値フィールド、共通の所持品セレクター、製作レシピセレクター、共通の照準 UI、共通の方向プロンプト、建設は、現在、構造化された記述を公開します。所持品 ID はフィルター後の操作可能な項目に結び付けられ、カテゴリ見出しには付与されません。単一項目ピッカーは `choose` を使い、ドロップ、拾得、アイテム使用の複数選択は既存の選択コールバックを通じて `set_count` を受け付けます。比較では項目を選べますが、数量には対応していません。製作の選択肢はネイティブのフィルター/タブ/ネスト順と製作可能状態を維持します。`set_count` は製作を開始せずに 1 から 50 のバッチモードを選び、その後の `choose` が通常の確認と材料検査を使います。対象の `set_target` は通常の射程と境界規則を通じて既存カーソルを動かすだけです。射撃、照準、投擲、安全確認は、登録済みアクションと通常のネストしたプロンプトのままです。方向の選択肢は水平方向の相対 8 ベクトルと現在地を含み、ネイティブの呼び出し元が垂直入力を許可する場合だけ上/下を含みます。建設の選択肢は現在のフィルター済み順序と利用可能状態を維持し、選択後はネイティブの確認、隣接配置、資材消費、拒否、活動処理に従います。設計図の選択には建設資材を必要としません。独立した地面の `PICKUP` ビューは、フィルター後のライブスタックだけを、種類、取得元、ネスト、着用/装備の検査、正確な利用可能数量と選択数量とともに公開します。`choose` はネイティブの親子トグル伝播を使い、`set_count` は 0 から利用可能数量までを選択します。`CONFIRM`、`WEAR`、`WIELD`、`SELECT_ALL`、フィルター処理は登録済みのネイティブアクションのままです。高度な所持品管理は、二つのネイティブペインからフィルター後のアイテム行を公開します。`choose` は対応するペインと行へフォーカスするだけです。移動には引き続き `MOVE_SINGLE_ITEM`、`MOVE_VARIABLE_ITEM`、`MOVE_ITEM_STACK` を使い、可変数量にはネイティブの整数ポップアップを使います。そのため、容量、液体、コンテナ、所有権、アクティビティ、再表示の処理はネイティブ経路に残ります。NPC 取引は、フィルター適用後の NPC/プレイヤーペイン、単価、選択済み数量と利用可能数量、残高、容量状態を公開します。`choose` はネイティブのアイテム切り替えを使い、複数個あるアイテムでは既存の数量フィールドを開きます。`set_count` は 0 から利用可能数量までの正確な数量を直接選択します。選択だけではアイテムを交換しません。登録済みの `CONFIRM` アクションが、ネイティブの信用、負債、NPC 容量、最終確認の検査を引き続き実行し、確認を受け入れた場合だけネイティブ取引へ進みます。

ヘルプは、読み込まれたトピックを不透明な ID の選択肢として公開します。`choose` は通常のトピック閲覧画面を開きます。ヘルプの閲覧画面と共通の読み取り専用 `SCROLLABLE_TEXT` は、`structured:true`、`kind:"custom"` と完全な `title`・`message` を返し、翻訳済みの内容、キー表示の置換、リンク、色のマークアップを保持します。アイテムの選択肢、数量、入力フィールド、照準情報は公開しません。公開された通常のページ移動・終了アクション、または `cancel` を使ってください。スクロールは入力境界を進めますが、テキストのスキーマは変更しません。終了すると呼び出し元に戻ります。入れ子の画面は独自の記述子、または明示的なアクションのみのフォールバックを公開します。

NPC との会話では、既に評価された現在の文章と利用可能な応答を取得できます。通常の画面に表示される試行の成功率や費用も含まれます。公開された `choice_id` を選んでください。同じ文面でも別の応答の場合があります。観察では会話を再評価せず、試行を振り直しません。「Look at」「Size up stats」「Yell」「Check opinion」は既存の会話トピックを使います。会話には `cancel` がないため、利用可能な別れや戻る応答を選びます。受理された選択は通常の確認、試行、効果、トピックの処理に従います。選択後は新しいスナップショットを取得してください。入れ子の確認にはそれぞれのコンテキストと ID があります。従来のキーボード操作とページ送りも使えます。

`MORALE` リーダーは構造化されており、`kind:"custom"` とネイティブ表示の完全な `title`・`message` を公開します。選択肢、数量、入力フィールド、対象はありません。登録済みのスクロール・終了アクション、または `cancel` を使ってください。受動的な読み取りは保存済みの意欲状態と RNG を変更しません。

未移行のカスタムビューは `structured:false`、`actions_only:true`、現在のコンテキスト、入力 ID を返します。明示的な互換フォールバックとして `bn.actions`/`bn.press` を使ってください。車両操作、キャラクター作成のカスタムビュー、その他の専用セレクターは、まだセマンティック方式へ移行されていません。

インタラクションまたは画面を確認して入力を一つ送り、次の入力を選ぶ前に結果のインタラクションを確認してください。一つの操作が別のメニューを開くことがあるため、アクション名とセマンティック ID は、各イベントが消費される時点でアクティブなコンテキストから解決されます。

たとえば、生のキーはメニューとプロンプトで機能します。

```json
{ "name": "bn.press", "arguments": { "keys": [{ "key": "ENTER" }] } }
```

プロファイルのキーバインドに従うには、`bn.actions` が返したアクションを使います。

```json
{ "name": "bn.press", "arguments": { "keys": [{ "action": "inventory" }] } }
```

アクションは現在のコンテキストに登録され、バインドされていなければなりません。キーボード入力を直接処理する画面には、生のキーで引き続きアクセスできます。`bn.actions` は現在の `input_id` と `timeout_ms` も返します。古い観察に基づく入力を拒否するには、イベントにこの ID を付けます。

```json
{ "name": "bn.press", "arguments": { "keys": [{ "action": "inventory", "input_id": 42 }] } }
```

例の値ではなく、実際に返された ID を使ってください。ネストしたプロンプトを含め、入力を読み取るたびに ID が進みます。意図的な `bn.press` の複数イベントバッチでは、最初のイベントだけを保護してください。すべてのイベントで同じ ID を再利用すると、二つ目のイベントが拒否されます。ID のないコマンドは `bn.press` の互換動作を維持します。セマンティックな `bn.interact` コマンドには常に ID が必要で、要求ごとに一つの操作だけが許可されます。このプロトコルは任意の Lua 評価を公開せず、隠されたワールドデータも明かしません。プレイヤーが利用できる情報を調べるには、ゲームの調査、マップ、キャラクター画面を使ってください。

テキスト入力には `text` イベントを送ります。

```json
{ "name": "bn.press", "arguments": { "keys": [{ "text": "Survivor" }] } }
```

マウス入力も同じ入力パイプラインを通ります。座標は端末セルです。

```json
{
  "name": "bn.press",
  "arguments": { "keys": [{ "mouse": { "x": 30, "y": 12, "button": "left" } }] }
}
```

対応するボタンは `left`、`right`、`scroll_up`、`scroll_down`、`move` です。一つのイベントは `action`、`key`、`text`、`mouse` のいずれかを指定します。プロンプトが物理キーと入力済み UTF-8 テキストの両方を必要とする場合、`key` イベントに `text` を添えることもできます。修飾キーはキーイベントで受け付け、テキストのみ、アクション、マウスのイベントでは拒否されます。

エージェントを待つ間、ゲームは入力境界で一時停止します。`bn.actions.timeout_ms` が `0` の場合は、アクションを要求せず非ブロッキングポーリングを一回完了するために `{"key":"IDLE"}` を送ってください。`IDLE` はブロッキング境界と正のタイムアウト境界では拒否されます。正の時間制限付きポーリングの満了を表すには `{"key":"TIMEOUT"}` を送ってください。一つのバッチは最大 256 イベントを受け付けます。各イベントは現在の画面に到達した時点で解決されます。イベントが不正な場合、残りのバッチは拒否されますが、先に適用されたイベントはそのまま残ります。

セーブと終了には、ゲームの通常のアクションと確認プロンプトを使います。MCP ホストを切断するとセッションは終了します。明示的なゲーム内セーブの代わりにはなりません。

セッションを記録するには、ゲーム起動時に `--replay-record PATH` を追加します。後で `--client=mcp --replay-play PATH` を使えば、ホストなしで実行できます。同一の初期プロファイルを準備して実セッションのスモーク検査を行う方法は、[リプレイガイド](replay.md)に従ってください。
