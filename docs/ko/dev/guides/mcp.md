---
title: MCP로 플레이하기
---

BN MCP 클라이언트를 사용하면 에이전트가 기존 화면과 조작 체계를 통해 게임을 실행할 수 있습니다. 캐릭터 생성, 월드 선택, 인벤토리, 제작, 조준, 대화, 저장은 대화형 클라이언트와 같은 게임 코드를 사용합니다.

`linux-clients` 프리셋을 사용하거나 [CMake를 구성](building/cmake.md)할 때 `MCP=ON`을 활성화한 다음 `cataclysm-bn` 대상을 빌드하세요. 타일 및 curses와 함께 활성화할 수 있으며 셋 모두 같은 엔진 빌드를 사용합니다. 공유 바이너리를 실행할 때 `--client=mcp`로 클라이언트를 명시적으로 선택하세요.

## 연결

MCP 호스트가 stdio 전송 방식으로 실행 파일을 시작하도록 구성하세요. 실행 파일, 데이터 디렉터리, 프로필에는 절대 경로를 사용하세요. 다음 예시의 경로를 체크아웃과 빌드 출력에 맞게 수정하세요.

`linux-clients` 프리셋을 사용하면 표준 바이너리 경로는 `out/build/linux-clients/src/cataclysm-bn`입니다.

```json
{
  "mcpServers": {
    "bn": {
      "command": "/path/to/Cataclysm-BN/out/build/linux-clients/src/cataclysm-bn",
      "args": [
        "--client=mcp",
        "--datadir",
        "/path/to/Cataclysm-BN/data/",
        "--userdir",
        "/path/to/bn-agent-profile/",
        "--configdir",
        "/path/to/bn-agent-profile/config/"
      ]
    }
  }
}
```

선택한 프로필에는 구성, 월드, 저장 파일, 캐릭터 템플릿이 들어 있습니다. 두 디렉터리 옵션을 항상 함께 전달하세요. XDG 빌드는 `--userdir`만 사용하면 계정의 일반 구성을 읽고 쓸 수 있습니다. 연결하기 전에 `--paths`를 한 번 추가해 실행하고 `Config Directory`가 프로필 안의 경로로 해석되는지 확인하세요. 일반 게임 시작 경로로 월드를 불러오려면 `--world NAME`을 추가하세요. 그렇지 않으면 시작 메뉴에서 월드와 캐릭터를 만들거나 선택하세요.

전송 방식은 [MCP stdio](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#stdio)를 사용합니다. stdin과 stdout에서 줄바꿈으로 구분된 JSON-RPC를 사용합니다. 각 입력 프레임은 끝의 줄바꿈 전까지 최대 1 MiB일 수 있습니다. 너무 크거나, 끝나지 않았거나, 읽을 수 없는 프레임은 세션을 0이 아닌 종료 상태로 닫으며 거부된 프레임의 접두부는 실행하지 않습니다. 게임 진단은 stderr로 출력됩니다. MCP 클라이언트는 게임 출력을 리디렉션하기 전에 원래 stdout을 복제하므로 Lua나 엔진 코드가 진단을 출력해도 프로토콜 stdout은 올바른 JSON-RPC로 유지됩니다. 터미널 창은 필요하지 않습니다.

## 플레이

| 도구             | 용도                                                                        |
| ---------------- | --------------------------------------------------------------------------- |
| `bn.observe`     | 현재 합성 화면을 읽습니다.                                                  |
| `bn.state`       | 플레이어에게 보이거나 알려진 구조화된 게임 상태를 읽습니다.                 |
| `bn.actions`     | 활성 컨텍스트, 액션 이름, 실제 키 바인딩을 찾습니다.                        |
| `bn.press`       | 일반 입력 파이프라인을 통해 키나 등록된 액션을 보냅니다.                    |
| `bn.interaction` | 화면을 해석하지 않고 실시간 구조화 선택지 또는 텍스트/숫자 필드를 읽습니다. |
| `bn.interact`    | 시맨틱 선택, 필드, 수량, 대상 또는 취소 작업을 적용합니다.                  |

`bn://screen` 리소스도 화면을 제공합니다. `rows`에는 UTF-8 텍스트가 들어 있고 `styles`는 전경색/배경색을 `[start_cell, length, foreground, background]` 런으로 보존합니다. 셀 인덱스는 왼쪽에서 오른쪽으로, 그다음 위에서 아래로 진행합니다. 좌표는 터미널 셀이며 전각 문자는 두 셀을 차지합니다. 커서 좌표는 텍스트 입력 및 선택 위치를 나타냅니다.

`bn://state` 리소스와 `bn.state` 도구는 아바타, 진행 중인 활동과 그 ID, 욕구, 신체 부위별 HP, 인벤토리와 중첩된 내용물, 착용/장착 장비, 보이는 맵의 지형/가구/통행 가능 여부/크리처/아이템, 알려진 오버맵 지형을 보고합니다. 시작 메뉴와 캐릭터 생성 중에는 `game_ready`가 false이며 월드와 아바타 설정이 완료된 뒤에만 true가 됩니다. 기본 상태 보기는 보이는 맵 반경 12셀과 알려진 오버맵 반경 8 OMT를 다루며 응답의 `coverage`에 이 범위가 포함됩니다. 가시성 검사는 보이지 않는 크리처와 보이지 않는 지형 뒤의 아이템을 제외합니다. 지면 아이템은 외부만 제공하고, 소유한 인벤토리와 장비는 중첩된 내용물도 포함합니다. 아바타와 보이는 맵 위치는 현실 버블의 맵 스퀘어를 사용하며 `avatar.absolute_position`은 버블이 이동해도 안정적으로 유지됩니다. 알려진 오버맵 위치는 절대 오버맵 타일을 사용합니다. `dimension`은 현재 차원을 나타냅니다.

`structured`가 true이면 `bn.interaction`을 우선 사용하세요. 선택지 설명자에는 불투명 ID, 레이블, 설명, 거부 사유, 실제 활성화 상태, 최종 선택 가능 여부, `selected`, `highlighted`가 포함됩니다. `selected`는 확정된 선택 상태를 나타내고 `highlighted`는 현재 탐색 포커스를 나타냅니다. 일반 단일 선택 메뉴에서는 현재 행이 두 필드에 모두 반영됩니다. 인벤토리 다중 선택기는 선택 수량이 0보다 클 때만 `selected`를 true로 설정합니다. 단일 항목 선택기는 열려 있는 동안 확정된 선택이 없으므로 포커스 행은 `choose`가 선택기를 닫을 때까지 `highlighted`만 true입니다. 수량을 지원하는 선택지에는 `selected_count`, 선택적인 `minimum_count`, `available_count`도 포함되며, `minimum_count`를 생략하면 0을 뜻합니다. 인벤토리 행의 `label`과 `columns`는 선택기의 행과 일치하며, `description`에는 일반 `EXAMINE` 액션이 표시하는 자세한 아이템 정보가 들어 있습니다. 전체 게임 내 보기는 해당 액션으로 계속 열 수 있습니다. 필드 설명자에는 현재 값, 텍스트 또는 정수 타입, 최대 표시 너비, 출력 가능한 문자 제한이 포함됩니다. 대상 설명자에는 현실 버블 맵 스퀘어 기준 원점과 커서, 사거리, 거리 규칙, 경계, 상태, 보이는 후보가 포함됩니다. 선택지 페이지는 기본적으로 항목 100개이며 `offset`과 `limit`을 받습니다. `choice_page.offset`과 `choice_page.total`은 반환된 위치와 전체 개수를 보고합니다. 두 패널 보기는 불투명한 패널 및 구역 ID, 보기별 역할(`source`, `destination`, `npc`, `player`), 구역 레이블과 설명, 필터, 명시적인 `storage_kind`(`inventory`, `worn`, `container`, `ground`, `cargo`, `mixed` 중 하나)를 담은 `panes`도 제공합니다. 각 선택지는 `pane_id`, 아이템의 실제 `area_id`, 해당 아이템의 `storage_kind`로 패널, 구역, 보관 위치를 참조합니다.

모든 `bn.interact` 요청은 현재 `input_id`와 정확히 하나의 작업을 제공합니다. `choose`는 스냅샷의 `choice_id`를 받고, `fill`은 `field_id`, `value`, 명시적인 `submit` 불리언을 받습니다. `set_count`는 `choice_id`와 음이 아닌 `count`를 받고, `set_target`은 정수 `x`, `y`, `z`를 가진 `position`과 선택적인 공개 `candidate_id`를 받습니다. `cancel`은 페이로드를 받지 않습니다. 수량 0은 인벤토리 항목 선택을 해제하지만, 공개된 `minimum_count`가 양수를 요구할 수 있습니다. 응답은 작업이 소비될 때까지 지연된 뒤 다음 안정된 상호작용 스냅샷을 반환합니다. 오래된 경계, 변경된 스키마나 대상 식별자, 알 수 없는 ID, 비활성 선택지, 잘못된 필드, 사용할 수 없는 수량, 사거리 또는 경계 밖 대상은 일부만 변경하지 않고 거부됩니다.

시작 루트/하위 메뉴, `uilist`, 일반 선택/확인/알림 팝업, `string_input_popup` 텍스트/숫자 필드, 공통 인벤토리 선택기, 제작법 선택기, 공통 조준 UI, 공통 방향 프롬프트, 건설은 현재 구조화된 설명자를 제공합니다. 인벤토리 ID는 필터를 통과한 조작 가능한 항목에만 연결되며 카테고리 머리글에는 연결되지 않습니다. 단일 항목 선택기는 `choose`를 사용하고, 버리기, 줍기, 아이템 사용 다중 선택기는 기존 선택 콜백을 통해 `set_count`를 받습니다. 비교는 항목 선택을 지원하지만 수량은 지원하지 않습니다. 제작 선택지는 네이티브 필터/탭/중첩 순서와 제작 가능 여부를 보존합니다. `set_count`는 제작을 시작하지 않고 1부터 50까지의 묶음 모드를 선택하며, 뒤이은 `choose`가 일반 확인 및 재료 검사를 사용합니다. 대상 `set_target`은 일반 사거리와 경계 규칙을 통해 기존 커서만 이동합니다. 발사, 조준, 투척, 안전 확인은 등록된 액션과 일반 중첩 프롬프트를 그대로 사용합니다. 방향 선택지는 수평 상대 벡터 8개와 현재 위치를 포함하며 네이티브 호출자가 수직 입력을 허용할 때만 위/아래를 포함합니다. 건설 선택지는 현재 필터된 순서와 이용 가능 상태를 보존하고, 선택 후에는 네이티브 확인, 인접 배치, 자원 소비, 거부, 활동 처리를 따릅니다. 청사진 선택에는 건설 재료가 필요하지 않습니다. 별도의 지면 `PICKUP` 보기는 필터를 통과한 실시간 스택만 타입, 출처, 중첩 관계, 착용/장착 검사, 정확한 가용 및 선택 수량과 함께 제공합니다. `choose`는 네이티브 부모/자식 토글 전파를 사용하고 `set_count`는 0부터 가용 수량까지 선택합니다. `CONFIRM`, `WEAR`, `WIELD`, `SELECT_ALL`, 필터링은 등록된 네이티브 액션을 그대로 사용합니다. 고급 인벤토리는 두 네이티브 패널에서 필터를 통과한 아이템 행을 제공합니다. `choose`는 연결된 패널과 행에 포커스만 맞추며, 전송은 계속 `MOVE_SINGLE_ITEM`, `MOVE_VARIABLE_ITEM`, `MOVE_ITEM_STACK`을 사용하고 가변 수량은 네이티브 정수 팝업을 사용합니다. 따라서 용량, 액체, 컨테이너, 소유권, 활동, 재진입 동작은 네이티브 경로에 남습니다. NPC 거래는 필터가 적용된 NPC/플레이어 패널, 단가, 선택/가용 수량, 잔액, 용량 상태를 제공합니다. `choose`는 네이티브 아이템 토글을 사용하며 여러 개가 있는 아이템에는 기존 수량 필드를 엽니다. `set_count`는 0부터 가용 수량까지 정확한 수량을 바로 선택합니다. 선택만으로는 아이템을 교환하지 않습니다. 등록된 `CONFIRM` 액션이 네이티브 신용, 채무, NPC 용량, 최종 확인 검사를 계속 수행하며, 확인을 수락한 경우에만 네이티브 거래가 실행됩니다.

도움말은 불러온 주제를 불투명한 ID의 선택지로 공개합니다. `choose`는 기존 주제 열람 화면을 엽니다. 도움말 열람 화면과 공통 읽기 전용 `SCROLLABLE_TEXT`는 `structured:true`, `kind:"custom"`과 전체 `title`, `message`를 반환하며 번역된 내용, 키 표시 치환, 링크, 색상 마크업을 보존합니다. 아이템 선택지, 수량, 입력 필드, 조준 정보는 공개하지 않습니다. 공개된 기존 페이지 이동·닫기 동작이나 `cancel`을 사용하세요. 스크롤은 입력 경계를 진행하지만 텍스트 스키마는 바꾸지 않으며, 닫으면 호출한 화면으로 돌아갑니다. 중첩 화면은 자체 설명 정보나 명시적인 동작 전용 폴백을 공개합니다.

NPC 대화에서는 이미 계산된 현재 대사와 선택 가능한 응답을 읽을 수 있습니다. 기존 화면에 표시되는 대화 시도의 성공률과 비용도 포함됩니다. 공개된 `choice_id`를 선택하세요. 문구가 같아도 서로 다른 응답일 수 있습니다. 관찰은 대화를 다시 계산하거나 시도를 다시 굴리지 않습니다. ‘Look at’, ‘Size up stats’, ‘Yell’, ‘Check opinion’은 기존 대화 화제를 사용합니다. 대화에는 `cancel`이 없으므로 선택 가능한 작별 또는 돌아가기 응답을 고르세요. 수락된 선택은 기존 확인 창, 시도, 효과, 화제 처리 절차를 따릅니다. 선택할 때마다 새 스냅샷을 조회하세요. 중첩 확인 창은 각자의 컨텍스트와 ID를 사용합니다. 기존 키보드 조작과 페이지 이동도 사용할 수 있습니다.

`MORALE` 읽기 보기는 구조화되어 있으며 `kind:"custom"`과 기존 화면의 전체 `title`, `message`를 제공합니다. 선택지, 수량, 입력 필드, 대상은 없습니다. 등록된 스크롤·닫기 액션이나 `cancel`을 사용하세요. 수동 조회는 저장된 사기 상태와 RNG를 변경하지 않습니다.

아직 이전되지 않은 사용자 지정 보기는 `structured:false`, `actions_only:true`, 현재 컨텍스트와 입력 ID를 반환합니다. 명시적인 호환 폴백으로 `bn.actions`/`bn.press`를 사용하세요. 차량 상호작용, 캐릭터 생성 사용자 지정 보기와 그 밖의 전용 선택기는 아직 시맨틱 방식으로 이전되지 않았습니다.

상호작용 또는 화면을 확인하고 입력 하나를 보낸 다음, 다음 입력을 고르기 전에 결과 상호작용을 확인하세요. 한 작업이 다른 메뉴를 열 수 있으므로 각 이벤트가 소비될 때 활성 상태인 컨텍스트에서 액션 이름과 시맨틱 ID를 해석합니다.

예를 들어 원시 키는 메뉴와 프롬프트에서 작동합니다:

```json
{ "name": "bn.press", "arguments": { "keys": [{ "key": "ENTER" }] } }
```

프로필의 키 바인딩을 따르려면 `bn.actions`가 반환한 액션을 사용하세요:

```json
{ "name": "bn.press", "arguments": { "keys": [{ "action": "inventory" }] } }
```

액션은 현재 컨텍스트에 등록되고 바인딩되어 있어야 합니다. 키보드 입력을 직접 처리하는 화면도 원시 키로 접근할 수 있습니다. `bn.actions`는 현재 `input_id`와 `timeout_ms`도 반환합니다. 이미 오래된 관찰을 바탕으로 한 입력을 거부하려면 이벤트에 이 ID를 붙이세요:

```json
{ "name": "bn.press", "arguments": { "keys": [{ "action": "inventory", "input_id": 42 }] } }
```

예시 값이 아니라 실제 반환된 ID를 사용하세요. 중첩 프롬프트를 포함해 입력을 읽을 때마다 ID가 증가합니다. 의도적인 `bn.press` 다중 이벤트 배치에서는 첫 이벤트만 보호하세요. 모든 이벤트에 같은 ID를 재사용하면 두 번째 이벤트가 거부됩니다. ID가 없는 명령은 `bn.press` 호환 동작을 유지합니다. 시맨틱 `bn.interact` 명령에는 항상 ID가 필요하며 요청당 작업 하나만 허용합니다. 프로토콜은 임의 Lua 평가를 제공하거나 숨겨진 월드 데이터를 공개하지 않습니다. 플레이어가 이용할 수 있는 정보를 살펴보려면 게임의 조사, 맵, 캐릭터 화면을 사용하세요.

텍스트를 입력하려면 `text` 이벤트를 보내세요:

```json
{ "name": "bn.press", "arguments": { "keys": [{ "text": "Survivor" }] } }
```

마우스 입력도 같은 입력 파이프라인을 따릅니다. 좌표는 터미널 셀입니다:

```json
{
  "name": "bn.press",
  "arguments": { "keys": [{ "mouse": { "x": 30, "y": 12, "button": "left" } }] }
}
```

지원하는 버튼은 `left`, `right`, `scroll_up`, `scroll_down`, `move`입니다. 이벤트 하나에는 `action`, `key`, `text`, `mouse` 중 하나를 제공합니다. 프롬프트에 물리 키와 입력한 UTF-8 텍스트가 모두 필요하면 `key` 이벤트에 `text`를 함께 넣을 수도 있습니다. 수정 키는 키 이벤트에 사용할 수 있으며 텍스트 전용, 액션, 마우스 이벤트에서는 거부됩니다.

게임은 에이전트를 기다리는 동안 입력 경계에서 일시 정지합니다. `bn.actions.timeout_ms`가 `0`이면 액션을 요청하지 않고 비차단 폴링 한 번을 완료하도록 `{"key":"IDLE"}`을 보내세요. `IDLE`은 차단 경계와 양수 시간 제한 경계에서 거부됩니다. 양수 시간 제한 폴링이 만료됐음을 나타내려면 `{"key":"TIMEOUT"}`을 보내세요. 한 배치에는 최대 256개 이벤트를 넣을 수 있습니다. 각 이벤트는 현재 화면에 도달할 때 해석됩니다. 이벤트가 잘못되면 남은 배치는 거부되지만 앞서 적용된 이벤트는 유지됩니다.

저장과 종료에는 게임의 일반 액션과 확인 프롬프트를 사용합니다. MCP 호스트 연결을 끊으면 세션이 끝납니다. 명시적인 게임 내 저장을 대신하지는 않습니다.

세션을 기록하려면 게임 실행 시 `--replay-record PATH`를 추가하세요. 나중에 호스트 없이 `--client=mcp --replay-play PATH`로 실행할 수 있습니다. 동일한 초기 프로필을 준비하고 실제 세션 스모크 검사를 실행하는 방법은 [리플레이 가이드](replay.md)를 따르세요.
